# Модуль AmneziaWG для ядра 3.10 (экспериментальный)

> ⚠️ **Не выгружайте модуль: при пакетах в очереди модема это паника ядра. Остановка — только `ip link del`, откат — перезагрузка.**

Статус: экспериментальный, работает на одном роутере. Вариант по умолчанию — `neon`, проверен на роутере прогоном на 164 МБ, ошибок ядра 0. Вариант `scalar` проверен прогоном на 89 МБ. Ошибка в модуле ядра может повесить роутер до выемки аккумулятора.

Для того, кто хочет держать AmneziaWG в ядре роутера вместо `amneziawg-go`. ЦП на мегабит чаще ниже, памяти свободнее на 5–11 МБ. Модулем управляет пакет `awg` [веб-панели](../webui/README.md), он же ставит его из `prebuilt/neon/`: [как включить](#через-пакет-awg). Без файла модуля пакет работает на `amneziawg-go`.

Основа — [amneziawg-linux-kernel-module](https://github.com/amnezia-vpn/amneziawg-linux-kernel-module), тег `v3.1.20260906`, лицензия GPL-2.0.

## Варианты

| вариант | шифры | состояние |
|---|---|---|
| `scalar` | только обычные ARM | проверен на роутере; запасной вариант, если `neon` даст ошибки ядра |
| `neon` | NEON, если он есть | по умолчанию, проверен на роутере; в ядре нет `CONFIG_KERNEL_MODE_NEON`: своя копия `kernel_neon_begin/end` из `vfpmodule.c`, символы через `kallsyms_lookup_name`; параметр `neon=0` выключает NEON |

На коротком замере скорость у вариантов одинаковая, 18–20 Мбит/с на приеме. Вариант `neon` меньше загружает процессор: 65–73 % против 76–77 % на том же замере. Предел туннеля: [VPN](../docs/vpn.md#что-ожидать-по-скорости).

В варианте `neon` модуль не должен вызывать `cond_resched()`, пока занят NEON: `cond_resched()` в ядре 3.10 не смотрит на счетчик запрета вытеснения. Иначе в журнале ядра появляется `BUG: scheduling while atomic`. Патч `neon` это учитывает.

## Что проверено

На роутере, вариант `scalar`:

| проверка | итог |
|---|---|
| `insmod` | код 0, `AmneziaWG 3.1.20260906 loaded` |
| самотесты шифров | все 5 `self-tests: pass`, около 1 с задержки при `insmod`: это норма |
| `ip link add ... type amneziawg`, `awg setconf`, `awg show` | работают с настоящими профилями протоколов 2.0 и 3.1 |
| туннель | рукопожатие есть, трафик идет, пока модуль в памяти паники нет |
| выгрузка модуля | один раз прошла без ошибок, в другой раз привела к панике ядра, см. ниже |

Замер: скачивание 8 МиБ через туннель.

| что | скорость, Мбит/с | ЦП, % |
|---|---|---|
| модуль, протокол 2.0 | 11,5–12,6 | 47–62 |
| модуль, протокол 3.1 | 11,9–12,8 | 56–63 |
| `amneziawg-go`, протокол 2.0 | 10,6–13,1 | около 70 |

Эти замеры короткие и занижают скорость. Предел туннеля: [VPN](../docs/vpn.md#что-ожидать-по-скорости).

Прогон через `svc.sh`, 25 мин без выгрузки, туннель постоянно на модуле: около 89 МБ, смены профилей, `stop` и `start`, переходы между `go` и `kernel` при загруженном модуле. Паник нет, память стабильна.

Прогон варианта `neon`: 13 циклов, 164 МБ, прием 18,6–20,5 Мбит/с, передача 5,9–8,1 Мбит/с. Плавающая точка: 39 проверок без расхождений. `Oops` и `BUG` 0.

Автозапуск проверен перезагрузкой: туннель поднялся к 26 с, на модуле, ошибок ядра 0. Настройка «Включать при загрузке роутера» по умолчанию выключена.

Паника после выгрузки. Модуль ставит пакетам деструктор `__compat_fake_destructor` (`compat/udp_tunnel/udp_tunnel.c`, строка 207). Пакет в очереди отправки модема (`ADS_UL`) держит ссылку на код модуля, а модуль уже был выгружен. Когда модем освободил пакет, ядро перешло по адресу в выгруженном модуле:

```text
ADS_UL_FreeIpfSrcMem -> mdrv_spe_wport_recycle -> __kfree_skb -> skb_release_head_state
destructor 0xbf0fa060, prefetch abort
Modules linked in: dhd(O) [last unloaded: amneziawg]
```

Пока модуль в памяти, адрес деструктора остается верным, поэтому остановка — `ip link del` без выгрузки. Роутер при этой панике перезагрузился сам, потому что `/proc/sys/kernel/panic` был равен 5.

Сверка по файлам для обоих вариантов:

| проверка | итог | как |
|---|---|---|
| `vermagic` `3.10.100+ preempt mod_unload ARMv7` | совпадает с ядром роутера | чтение `.ko` |
| 172 символа `scalar`, 174 `neon` | все есть в экспортах ядра роутера | список `__ksymtab_` |
| типы перемещений | все поддержаны `arch/arm/kernel/module.c` | чтение `.ko` |
| раскладка `sk_buff`, `net_device`, `sock`, `udp_sock`, `genl_family` и других | совпадает с ядром | код функций дерева E5885 с конфигурацией роутера против образа, см. `cmpfunc.txt` |

## Сборка

Нужны:

| что | откуда |
|---|---|
| дерево ядра | `kernel_3.10.100.tar.gz` в архиве `E5885Ls-93a_open_src.rar`, `ftp://serv.valdikss.org.ru/Downloads/Huawei_Open_Source/` |
| тулчейн `arm-eabi-4.7` | AOSP `prebuilts/gcc/linux-x86/arm/arm-eabi-4.7`, коммит `8b880805`: тот же `gcc version 4.7`, что в баннере ядра роутера |

```bash
tar -xzf kernel-module/src/awg-kmod-v3.1.20260906.tar.gz
cd amneziawg-linux-kernel-module-3.1.20260906/src
patch -p1 < ../../kernel-module/patches/awg-3.1.20260906-3.10-balong-neon.patch
cd ../..
kernel-module/build.sh КАТАЛОГ_ЯДРА КАТАЛОГ_СБОРКИ КАТАЛОГ_ТУЛЧЕЙНА kernel-module/router.config "$PWD/amneziawg-linux-kernel-module-3.1.20260906/src"
```

Результат: `amneziawg.ko` в каталоге модуля. В готовых модулях пути сборки начинаются с `/mnt` и `/srv`, поэтому ваша сборка побайтно не совпадет: в модуле остаются пути файлов.

## Через пакет `awg`

Команды — на компьютере, из каталога `webui/`:

```bash
src/pkg/get-bins.sh --only=awg --module
src/installer/install.sh --only=pkg --pkg-only=awg
```

`get-bins.sh --module` берет модуль из `../kernel-module/prebuilt/neon/`. Вариант `scalar` ставится так: `--module=../kernel-module/prebuilt/scalar/amneziawg.ko`.

| что | как работает |
|---|---|
| `ENGINE` в настройках пакета | `auto` — модуль, а если он не сработал — `amneziawg-go`; `kernel` — только модуль; `go` — только `amneziawg-go` |
| `svc.sh start` | пишет 5 в `/proc/sys/kernel/panic`, загружает модуль, создает `awg0` |
| `svc.sh stop`, `use`, переход на `go` | удаляется только `awg0`, модуль остается в памяти |
| `svc.sh status`, `brief` | поле `engine=kernel` или `engine=go` |
| убрать модуль | только перезагрузка роутера |

Подробно — [`webui/src/pkg/awg/README.md`](../webui/src/pkg/awg/README.md).

## Запуск вручную

Этот путь нужен для опытов, панель такой туннель не видит. Команды — на роутере, после установки пакета `awg` [веб-панели](../webui/README.md).

| подстановка | что это |
|---|---|
| `ФАЙЛ` | конфигурация только с ключами, которые понимает `awg`: без `Address`, `DNS`, `MTU`, `Table`, `PostUp` |
| `АДРЕС`, `ЗНАЧЕНИЕ` | `Address` и `MTU` вашего профиля |

1. Скопируйте `prebuilt/neon/amneziawg.ko` в `/tmp`: файл живет до перезагрузки, автозагрузки нет.

2. Остановите туннель панели: один ключ не может работать в двух туннелях сразу.

   ```bash
   busyboxx sh /online/mod/pkg/awg/svc.sh stop
   ```

3. Включите перезагрузку при панике: так роутер перезагрузится, а не зависнет до выемки аккумулятора. По умолчанию здесь 0:

   ```bash
   echo 5 > /proc/sys/kernel/panic
   ```

4. Загрузите модуль и посмотрите самотесты. Ожидается 5 строк `self-tests: pass` и `AmneziaWG 3.1.20260906 loaded`. Если самотест не прошел, модуль не загрузится:

   ```bash
   /system/bin/insmod /tmp/amneziawg.ko
   dmesg | tail -20
   ```

5. Создайте туннель:

   ```bash
   /system/bin/ip link add awg9 type amneziawg
   /online/mod/pkg/awg/bin/awg setconf awg9 ФАЙЛ
   /system/bin/ip addr add АДРЕС/32 dev awg9
   /system/bin/ip link set dev awg9 mtu ЗНАЧЕНИЕ up
   /online/mod/pkg/awg/bin/awg show awg9
   ```

   В выводе `awg show` есть `latest handshake`. Маршруты в туннель задайте сами: `svc.sh` этот туннель не обслуживает.

6. Остановите туннель и верните туннель панели. Модуль остается в памяти до перезагрузки:

   ```bash
   /system/bin/ip link del awg9
   busyboxx sh /online/mod/pkg/awg/svc.sh start
   ```

Откат — перезагрузка роутера: автозагрузки нет, и значение `/proc/sys/kernel/panic` вернется к 0.

Сообщите результат в теме 907081 на 4PDA.

## Ограничения

- Дерево ядра взято от соседней модели E5885Ls-93a. В конфигурации роутера есть 4 выключенных символа, которых нет в этом дереве: `ATP_CLAT`, `ATP_MBB_WLAN_DBHO`, `ATP_WLAN_BCM_DBHO`, `BR_NF_DEFRAG_IPV6_AUTH`. На раскладку структур они не влияют, это проверено сверкой кода.
- Запасной переход на `amneziawg-go`: переход и связь с сервером есть, выход в интернет через туннель на этом пути не подтвержден.
- `wireguard.ko` из мода и этот модуль — разные модули. `ip_tunnel.ko` для `amneziawg.ko` не нужен.
- Предупреждения сборки остаются в `device.c` (`netlink_ext_ack`, безвредно) и в `selftest/blake2s.c`.
