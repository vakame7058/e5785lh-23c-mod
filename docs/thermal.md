# Ложные выключения от перегрева

Для владельца E5785Lh-23c, чей роутер сам выключается при холодной батарее. Здесь причина и проверка, исправление — в шагах 5–9 [исправления NV](nv-fix.md#порядок).

## Признаки

- Роутер выключается через минуты после включения или после открытия страниц, которые читают температуру.
- На внешнем питании он затем включается снова.
- В журнале модема `/mobilelog/mobilelogger.log` есть строка:

  ```text
  The Vote is Power OFF due to thermal protection [352(current temp) >= 61(threshold)]
  ```

  Число в скобках (350–363) вдесятеро больше настоящей температуры батареи.

## Причина

Защиту от перегрева проводит модем: функция `Spy_CheckTemp`, настройки в NV 40 (`включена`, порог 61 °C). Она читает канал температуры из общей памяти. Таблицы и карту каналов туда кладет `fastboot`, и берет он их не из `nv.bin`, а из раздела `nvsys`.

```text
nv.bin (nvimg) ──► ядро: NV в памяти ──► модем: NV 40, порог 61
nvsys ──────────► fastboot: карта каналов и таблицы датчиков
```

После чужой прошивки и правки ячеек в `nv.bin` верные значения, а `nvsys` старый. Батарея считается по таблице другого датчика: она в десятых долях градуса, а порог в градусах. Защита срабатывает после 30 замеров подряд выше порога, примерно через 30 с.

Запускает ошибку чтение датчика без канала: драйвер перечитывает карту каналов из NV в памяти, и батарея переключается на неверную таблицу. Такой датчик — `/sys/class/thermal/temp:xo0_low`, `temp:xo1`, `temp:xo1_low`.

Запись системной ячейки NV 50018 через `/dev/nv` заставляет ядро переписать `nvsys` всем NV из памяти. После перезагрузки `fastboot` и ядро видят одну карту каналов.

## Проверка

На роутере после перезагрузки:

```bash
/system/xbin/atc 'AT^CHIPTEMP?'
/system/xbin/atc 'AT^TEMPINFO?'
cat /sys/class/power_supply/battery/temp
```

| что смотреть | норма | до исправления |
|---|---|---|
| 5-е поле `^CHIPTEMP` | равно `battery/temp`, например 35 | 9 |
| `^TEMPINFO`, `BAT` | 350 (десятые доли градуса) | 90 |
| `^TEMPINFO`, `USB` | около 350 | 0 |
| `AT^ADCTEMP?` | `1,60,53,50` | тот же |

## Какие датчики читать

| файл в `/sys/class/thermal/` | единицы | читать |
|---|---|---|
| `temp:battery/val` | °C | можно |
| `temp:sim_card1/val` | °C | можно |
| `temp:pa0/val` | десятые доли °C | можно |
| `temp:xo0/val` | десятые доли °C | можно |
| `temp:lcd`, `temp:pa1`, `temp:xo0_low`, `temp:xo1`, `temp:xo1_low` | нет канала | нельзя |

После исправления датчики без канала отвечают `EPERM`, без выключения. Читать их незачем. До исправления чтение приводит к выключению.

## Ограничения

- Проверка `Spy_E5_CheckSIMTemp` для SIM (порог 75 °C) идет отдельно и в этой неисправности не участвует.
- Причина самостоятельного включения на внешнем питании — NV 50364 (`no_battery_powerup_enable`). Это догадка по коду, на роутере не проверялась.
