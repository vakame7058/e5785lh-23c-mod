# Исправление NV после чужой прошивки

Для владельца E5785Lh-23c, у которого после прошивки от 22c модем не держит сеть. Инструкция возвращает ячейки платы из официального пакета, затем обновляет резервные копии NV. Выполните ее и тогда, когда роутер [выключается сам](thermal.md).

## Признаки

| признак | где смотреть |
|---|---|
| имя модели пустое | `ATI` на порту AT: поле `Model` пустое |
| сеть не поднимается, RSRP около −122 дБм, SINR около −9 дБ | веб-интерфейс; `/system/xbin/atc 'AT^HCSQ?'` на роутере |
| в журнале отказы `^REJINFO ... 302` | порт AT, `/mobilelog/mobilelogger.log` |
| смена настроек Wi-Fi дает код `100006` | веб-интерфейс |

## Причина

Плата 23c опознается как `product_id=33`: `/proc/device-tree/board_info`, поле `hisi,boardid`, значение `0x21`. Пакет 22c содержит секцию только для `product_id=3`. После его установки в `nv.bin` остаются значения эталонной платы: чужой тракт RF, другой список диапазонов, пустое имя продукта.

Значения для своей платы лежат в официальном пакете 23c, в файле `Nvdload_R11.bin`, секции `cat0` и `product_id=33`. Ячейки экземпляра (IMEI, калибровка) в секции не входят и не меняются.

## Порядок

Команды на роутере идут по SSH, вход настраивается пунктом «Ключ SSH» меню экрана мода (см. [меню экрана](oled-menu.md#вход-по-ssh)). `busyboxx` и `balong-nvtool` — из мода bay v5.

1. Снимите копии NV (на компьютере). Храните их у себя: в них IMEI и данные SIM.

   ```bash
   mkdir nvbackup
   ssh root@192.168.1.1 'cat /mnvm2:0/nv.bin' > nvbackup/nv.bin
   for n in 3 4 5 6 7; do
       ssh root@192.168.1.1 "busyboxx dd if=/dev/block/mtdblock$n" > nvbackup/mtd$n.bin
   done
   ```

   Номера: 3 `nvbacklte`, 4 `nvdefault`, 5 `nvimg`, 6 `nvdload`, 7 `nvsys`.

2. Достаньте `Nvdload_R11.bin` (на компьютере). Подойдет мод или официальный пакет 21.191.63.02. `balong_flash` собирает `tools/recovery/bin/build.sh`:

   ```bash
   mkdir parts && cd parts
   balong_flash -e ../E5785Lh-92a-23c_E5783h-92a_UPDATE_21.191.63.02.00.BIN
   cd ..
   ```

3. Составьте правку (на компьютере):

   ```bash
   python3 tools/nv/nvfix_gen.py --live nvbackup/nv.bin --nvdload parts/08-*-Nvdload_R11.bin --out nvfix
   ```

   Ожидаемый вывод на прошивке 21.191.63.02 после пакета 22c: `ячеек в секциях: 727; менять: 486` (у вас число может отличаться). Каталог `nvfix` содержит значения вашего экземпляра: не выкладывайте его.

   Если есть копия `nv.bin`, снятая до чужой прошивки на этом же роутере, добавьте `--orig КОПИЯ`. Тогда ячейки вернутся к вашим исходным значениям.

4. Запишите ячейки (на компьютере):

   ```bash
   tar -C nvfix -cf - . | ssh root@192.168.1.1 'busyboxx mkdir -p /online/nvfix && cd /online/nvfix && busyboxx tar -xf -'
   ssh root@192.168.1.1 'busyboxx sh /online/nvfix/apply.sh'
   ```

   Ожидаемый вывод: `записано ячеек: 486, ошибок: 0`.

5. Перезагрузите роутер, чтобы ядро подняло новый `nv.bin` в память:

   ```bash
   ssh root@192.168.1.1 'busyboxx setsid busyboxx sh -c "sleep 2; sync; busyboxx reboot -f" &'
   ```

6. Проверьте сеть (на роутере). Ожидается: `ATI` показывает `Model: E5785`, `AT^HCSQ?` — значения LTE, в течение минуты появляется интернет:

   ```bash
   /system/xbin/atc 'ATI'
   /system/xbin/atc 'AT^HCSQ?'
   ```

7. Сразу обновите `nvsys` и `nvbacklte`: без этого роутер может [выключаться сам](thermal.md). Запись ячейки `50018` тем же значением заставляет ядро переписать `nvsys` всем NV из памяти (на компьютере):

   ```bash
   ssh root@192.168.1.1 'busyboxx dd of=/tmp/nv50018_req.bin' < tools/nv/nv50018_req.bin
   ssh root@192.168.1.1 'busyboxx dd if=/tmp/nv50018_req.bin of=/dev/nv bs=46 count=1'
   ssh root@192.168.1.1 'i=0; while [ -e /modem_log/drv/nv/sys_flag.bin ] && [ $i -lt 30 ]; do busyboxx usleep 500000; i=$((i+1)); done; ls /modem_log/drv/nv/; /system/xbin/atc "AT^NVBACKUP"'
   ```

   `dd` пишет 46 Б без ошибки, файла `sys_flag.bin` в списке нет, `AT^NVBACKUP` отвечает `OK`.

8. Сверьте `nvsys` с `nv.bin` до перезагрузки (на компьютере):

   ```bash
   ssh root@192.168.1.1 'cat /mnvm2:0/nv.bin' > nv_now.bin
   ssh root@192.168.1.1 'busyboxx dd if=/dev/block/mtdblock7' > nvsys_now.bin
   python3 tools/nv/nvsys_check.py nvsys_now.bin nv_now.bin
   ```

   Ожидаемый итог: `ИТОГ: годится`. Если итог другой, не перезагружайтесь и пишите в тему форума.

9. Перезагрузите роутер, как в шаге 5. Проверьте температуру: [как проверить](thermal.md#проверка).

Откат: соберите правку обратно и повторите шаги 4, 5, 7, 8, 9:

```bash
python3 tools/nv/nvfix_gen.py --live nv_now.bin --nvdload parts/08-*-Nvdload_R11.bin --orig nvbackup/nv.bin --restore --out nvundo
```

После любой другой правки `nv.bin` через `balong-nvtool` повторите шаги 5, 7, 8, 9.

## Чем писать NV

| способ | работает | примечание |
|---|---|---|
| `balong-nvtool -r <id>:<файл>` + перезагрузка | да | файл ровно длины ячейки |
| `balong-nvtool -m <id>:<байт>:<байт>...` + перезагрузка | да | так пишет пункт «Привязка к соте» |
| `balong-nvtool -w <каталог>` | частично | берет только файлы с 5-значным именем (`00013.nvm`), остальные молча пропускает |
| `balong-nvtool -f` (перечитать NV в модем) | нет | ядро отвечает «not in white list» |
| `AT^NVRD`, `AT^NVWR` | нет | `^DATALOCK:1`; патч мода пишет в `/dev/kmem`, которого нет |
| запись в `/dev/nv` | только системные ячейки | см. ниже |

## Что нельзя

| действие | что будет |
|---|---|
| запись NV 36 через `/dev/nv` | ядро всегда отвечает `EPERM`: запрет `id == 36` в `nv_writeEx` |
| `AT^INFORBU` | перезаписывает `nvdefault`, заводскую копию NV |
| запись в `/proc/nvresumeflag`, `/proc/nvresumeport` | включает восстановление NV при загрузке |
| прошивка через режим прошивки и восстановление NV из резервной копии, пока `nvsys`, `nvbacklte` старые | вернутся неверные значения |

Формат запроса к `/dev/nv`: `u32 индекс`, `u32 длина`, `u32 0`, данные. Файл `nv50018_req.bin` — это индекс 93 (`0x5d`), длина 34, затем 34 нулевых байта. В этой ячейке лежит своя строка версии прошивки, у официальной прошивки она пустая.

## Ограничения

- На проверенном роутере записаны исходные значения из его копии (режим `--orig`). В 11 ячейках они отличаются от XML: `2312`, `2356`, `8451`, `10465`, `50344`, `50462`, `53978`, `57189`, `62554`, `62557`, `62559`. Запись значений из XML на роутере не выполнялась.
- При следующих загрузках модем сам меняет ячейки `8302`, `8452`, `9017`. Это история сети, повторный запуск `nvfix_gen.py` может показать их снова.
- Раздел `nvdload` остается от прошлой прошивки. Он не влияет на работу, пока NV не обновляют пакетом.
- Маска диапазонов LTE в настройках после исправления — `0x2000000045` (B1, B3, B7, B38). Плата умеет еще B8, B20, B28, B32, полная маска `0x20880800C5`. Включение — по желанию, через настройки веб-интерфейса.
