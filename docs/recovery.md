# Восстановление из режима прошивки

Для владельца E5785Lh-23c, чей роутер после чужой прошивки (обычно от 22c) не загружается в обычный режим, и для тех, кто ставит мод со стоковой прошивки.
Инструкция возвращает цепочку загрузки 21.191.63.02 и мод bay v5. Следующий шаг после нее — [исправление NV](nv-fix.md).

> ⚠️ Только для E5785Lh-23c (плата `CL1E5785SM VER.A`, dload id `E5785__0`). На 22c (dload id `E5785B__0`) другой экран, другая кнопка сброса и другая раскладка разделов.

## Признаки

| что видно | что это значит |
|---|---|
| белый экран, USB `12d1:1c05`, порт `ttyUSB1` отвечает кадрами HDLC | роутер в режиме прошивки |
| USB `12d1:1c20` «Mobile WiFi (Charging)» появляется на 2 с каждые 22 с | система в режиме зарядки перезапускается |
| черный экран, USB нет, а иголка дает `12d1:1443` | цепочка загрузки испорчена |

## Со стоковой прошивки

Порядок тот же: BootROM работает при любом содержимом флеша, и запись одинакова для исправного и испорченного роутера. Со стоковой прошивки этот порядок не проверялся: его прошли на роутере, испорченном прошивкой от 22c.

| шаг | что иначе |
|---|---|
| до записи | Снимите копию начала флеша с загрузчиками, NV и `oeminfo`: войдите в BootROM, поднимите fastboot и выполните `python3 tools/recovery/dump_pages.py 0 12160 work/start.dump`. Затем отключите USB и начните запись с нового входа в BootROM: чтение портит запись в том же сеансе. |
| `oeminfo` | Как в разделе [«Запись»](#запись): сотрите. Содержимое остается в копии. |
| [исправление NV](nv-fix.md) | Пропустите, если прошивка от 22c на роутер не ставилась: NV остаются родными. |

Копию из `dump_pages.py` не пишите обратно через `rawflash_ex`: она нужна, чтобы достать из нее данные разделов.

## Что понадобится

| что | откуда | зачем |
|---|---|---|
| `balong-usbdload` | готовый: `tools/recovery/bin/balong-usbdload`, Linux x86-64. Запасной путь: `make` в [forth32/balong-usbdload](https://github.com/forth32/balong-usbdload) | загрузка в память через BootROM |
| `usblsafe-e5785.bin` | только по ссылке: [forth32/balong-usbdload](https://github.com/forth32/balong-usbdload) | исходный загрузчик для правки |
| `balong_flash` | собрать: `tools/recovery/bin/build.sh КАТАЛОГ`, или `make` в [forth32/balongflash](https://github.com/forth32/balongflash) | разбор файла прошивки на разделы |
| мод `E5785Lh-92a-23c_E5783h-92a_UPDATE_21.191.63.02.00.baymod.v5.fw` | 4PDA, тема 907081, пост 95373571 | все разделы, кроме `webui` |
| `modwebui_1.5a.zip` | 4PDA, тема 907081, пост 80753809 | раздел `webui`; без него экран черный |
| `fastboot`, Python 3 | пакеты системы | запись и сверка; для сверки нужен `pyusb` |

Файлы Huawei в комплект не входят. Официальный пакет 21.191.63.02 лежит там же, пост 95351901; в моде все разделы, кроме `System` и `APP`, побайтно совпадают с ним.

Правило доступа к USB для обычного пользователя (файл `/etc/udev/rules.d/51-huawei-e5785.rules`):

```text
SUBSYSTEM=="usb", ATTR{idVendor}=="12d1", MODE="0660", GROUP="plugdev"
SUBSYSTEM=="tty", ATTRS{idVendor}=="12d1", MODE="0660", GROUP="plugdev"
```

## Подготовка образов

Все команды — на компьютере, из корня комплекта, каталог `work` создайте сами.

1. Соберите загрузчик с таблицей разделов 23c. Скрипт меняет 4 байта и сверяет контрольные суммы:

   ```bash
   python3 tools/recovery/patch_usblsafe_ptable23c.py usblsafe-e5785.bin work/usblsafe-e5785-ptable23c.bin
   ```

2. Разберите мод на разделы. Файлы лягут в текущий каталог как `NN-XXXXXXXX-Имя.bin`:

   ```bash
   tools/recovery/bin/build.sh work/bin
   cd work && bin/balong_flash -e ../E5785Lh-92a-23c_E5783h-92a_UPDATE_21.191.63.02.00.baymod.v5.fw && cd ..
   ```

3. Соберите образ `m3boot`: 4 копии M3Boot с таблицей разделов 23c. Он нужен, потому что чужая прошивка записала в `m3boot` таблицу 22c:

   ```bash
   python3 tools/recovery/mkm3boot.py work/01-*-M3Boot_R11.bin work/02-*-M3Boot-ptable.bin work/m3boot.img
   ```

4. Соберите образы YAFFS2. `System.bin`, `APP.bin` и `Modem_fw.bin` в прошивке — архивы cpio, fastboot пишет только образы со страницами 2048+16 Б:

   ```bash
   for p in System APP Modem_fw; do
       python3 tools/recovery/mkyaffs_hw.py build work/*-$p.bin work/$p.y2064
       python3 tools/recovery/mkyaffs_hw.py verify work/*-$p.bin work/$p.y2064
   done
   ```

5. Соберите образ `webui` из архива `modwebui_1.5a.zip`. Внутри него лежит `webui.tgz` с каталогами `WebApp` и `data`:

   ```bash
   mkdir work/webui && unzip -q modwebui_1.5a.zip -d work/webui
   tar -xzf work/webui/modwebui_1.5a/webui.tgz -C work/webui --no-same-owner
   (cd work/webui && find WebApp data -print | cpio -o -H newc --owner 0:0 --quiet) > work/webui.cpio
   python3 tools/recovery/mkyaffs_hw.py build work/webui.cpio work/WebUI.y2064
   python3 tools/recovery/mkyaffs_hw.py verify work/webui.cpio work/WebUI.y2064
   ```

   `verify` печатает «расхождений: 0».

## Вход в BootROM

1. Выключите роутер и отключите USB. Снимите крышку.
2. Замкните иголкой площадку RX UART на плате на землю.
3. Подключите USB, не убирая иголку.
4. Дождитесь `12d1:1443` в `lsusb` и `/dev/ttyUSB0`, затем уберите иголку.

Расположение площадки смотрите в теме 4PDA 907081. BootROM находится в кристалле и работает при любом содержимом флеша. Аккумулятор при этом может оставаться в роутере.

## Что запускается после иголки

Иголка всегда дает одно и то же: BootROM в кристалле, `12d1:1443`. Дальше режим выбирает `balong-usbdload`:

| запуск | что поднимается | USB |
|---|---|---|
| с ключом `-f` | `usblsafe` останавливается на fastboot, Linux не запускается | `12d1:36dd` |
| без ключа `-f` | `usblsafe` запускает мини-Linux с портом прошивки HDLC | `12d1:1c05` |

Эта инструкция использует `-f`: на проверенном роутере порт USB мини-Linux с этим загрузчиком не заработал, подмена ядра и дерева устройств в загрузчике не помогла. Другие модели на этом не проверялись.

`usblsafe-e5785.bin` собран под 22c. Его таблица разделов не совпадает с 23c в размере `app`, начале `webui` и начале и размере `system`, поэтому его сначала правит `patch_usblsafe_ptable23c.py`.

Белый экран с `12d1:1c05` — другой случай: роутер сам загрузился в режим прошивки с флеша, без иголки.

## Подъем fastboot в памяти

Загрузчик попадает только в память, флеш не меняется:

```bash
tools/recovery/bin/balong-usbdload -p /dev/ttyUSB0 -f -c work/usblsafe-e5785-ptable23c.bin
```

Проверка: `lsusb` показывает `12d1:36dd`, `fastboot getvar version` отвечает `0.9`. Если к компьютеру подключен сканер отпечатков или другое устройство fastboot, укажите порт: `fastboot -s usb:1-2 ...`.

## Запись

Пишите сразу после подъема fastboot, до любых чтений (см. [правила](#правила-записи)).

1. Сотрите `oeminfo`. С пустым `oeminfo` роутер работает:

   ```bash
   fastboot erase oeminfo
   ```

2. Запишите все разделы:

   ```bash
   tools/recovery/flash_fw.sh work work --m3boot work/m3boot.img
   ```

   Скрипт пишет `m3boot`, `fastboot`, `m3image`, `dts`, `teeos`, `kernel`, `logo`, затем стирает и пишет `modem_fw`, `system`, `app`, `webui`. Порт для fastboot задается переменной `FASTBOOT_S`.

Каждая строка записи заканчивается `OKAY`. Чтобы вернуть официальную систему без мода, разберите официальный `.BIN` и подставьте его файлы.

## Сверка

Читайте только после записи. Чтение в том же сеансе портит следующую запись, поэтому повторную запись начинайте с нового входа в BootROM.

Команда чтения: `dump_pages.py АДРЕС СТРАНИЦ ФАЙЛ`, адрес в шестнадцатеричном виде, страниц — размер образа, деленный на 2048 с округлением вверх. Для образов YAFFS2 размер образа делите на 2064.

```bash
python3 tools/recovery/dump_pages.py 17c0000 3219 work/kernel.dump
python3 tools/recovery/verify_flash.py work/06-*-Kernel_R11.bin work/kernel.dump

python3 tools/recovery/dump_pages.py b040000 5405 work/app.dump
python3 tools/recovery/verify_flash.py --yaffs work/APP.y2064 work/app.dump
```

Ожидаемый итог: `расходятся: 0`. Расхождение по смещению `0x2000` — след слова `OKAY`: запись шла после чтения.

## Первое включение

1. Отключите USB, выньте аккумулятор на минуту, вставьте его обратно.
2. Включите роутер кнопкой питания. `fastboot reboot` не годится: это теплый перезапуск, и флаг режима прошивки остается.
3. Первая загрузка: логотип около 15 с, затем подсветка.
4. На компьютере появятся порт AT, сеть NCM (интерфейс `wwx...`) и CD-ROM, USB `12d1:1506`.

Адрес роутера в сети USB — `192.168.1.1`. Компьютеру задайте адрес сами: `ip addr replace 192.168.1.200/24 dev wwxИМЯ`. Если компьютер остается на `12d1:15ca`, проверьте запись `usb_modeswitch`.

Дальше, если ставилась прошивка от 22c: [исправление NV](nv-fix.md). До него модем не держит сеть, а защита от перегрева работает неверно.

## Правила записи

| правило | почему |
|---|---|
| писать сразу после подъема fastboot, до `nanddump` и `memupload` | после чтений fastboot кладет `OKAY` в 4 байта по смещению `0x2000` образа: так портятся `m3boot`, `fastboot`, ядро |
| сверять чтением байт в байт, без допусков | допуск на первые байты страницы скрывает порчу |
| перед записью YAFFS2 делать `erase` | старые блоки с большим номером последовательности перекрывают новые |
| `system`, `app`, `webui`, `modem_fw` — образ 2064 из `mkyaffs_hw.py` | у этих разделов в таблице 23c флаг `0x4001`, сырой cpio дает `flash write failure` |
| цепочка `m3boot`…`kernel` из одной прошивки | загрузчики разных сборок несовместимы |
| копию из `nanddump` не писать через `rawflash_ex` | в ней нет байтов ECC, запись их испортит |
| `oem efuse`: не вызывать ключ `m` и смену LCS | запись eFuse необратима |

Что видно в `nanddump`:

- `oem nanddump:<адрес>:<длина>:40` отдает страницы по 2112 Б, значимы только первые 16 Б OOB.
- Плохой блок fastboot пропускает, в дампе на его месте копия предыдущего блока. `verify_flash.py` такие блоки узнает.

## Как загружается роутер

```text
BootROM ──► m3boot (M3) ──► fastboot (A9) ──► m3image, teeos, dts, kernel
                                         └──► ramdisk обычный или ramdisk_dload (режим прошивки)
```

Режим прошивки включает флаг `NFLD` в общей памяти. Его ставят:

- `m3boot`: запись `NMCP` в `oeminfo`;
- `fastboot`: запись `NMCP` и `MFUA` в `oeminfo`, метка `0x82822828` по адресу `0x1001fff8`, кнопка сброса у сборок 22c, счетчик теплых перезапусков.

Флаг переживает теплый перезапуск.

## Ограничения

- Загрузка готовой статической сборкой `tools/recovery/bin/balong-usbdload` на роутере не запускалась. На нем работала сборка из того же коммита.
- Порядок проверен на одном роутере: плата `CL1E5785SM VER.A`, исходная прошивка `V700R220C60B182`, сборка `C260`.
- Запись шла двумя сеансами: цепочка загрузки, затем `system`, `app`, `webui`. `flash_fw.sh` объединяет их и на роутере не запускался, проверен на заглушке `fastboot`. Команды те же.
- `nvdload` и `fastbootbk` инструкция не трогает. `kernelbk`, `dtsbk`, `m3imagebk`, `teeosbk` остаются как были.
