# awg: VPN AmneziaWG на роутере

Роутер подключается к серверу AmneziaWG как клиент и пускает в туннель трафик клиентов Wi-Fi и USB.
AmneziaWG — WireGuard с маскировкой от DPI. Пакет понимает протокол до версии 3.1 и старые конфиги 1.x и 2.0.
Без файла `amneziawg.ko` туннель держит `amneziawg-go` в пространстве пользователя. Если положить этот модуль ядра в пакет, туннель держит он, а при сбое пакет переходит на `amneziawg-go`.
Вместо `awg-quick` (ему нужен bash) адрес, маршруты, NAT и DNS настраивает `svc.sh`.

```text
клиент LAN ──► br0 ── ip rule 5300: в сеть LAN → main (управление роутером мимо туннеля)
                  └── ip rule 5301: остальное → таблица 5300 ─► default dev awg0 ─► модуль или amneziawg-go ─UDP─► eth_x ─► сервер
                                                     └─ unreachable (блокировка утечки, если туннель пропал)
сам роутер ──► main ─► eth_x напрямую (ROUTE_SELF=0) или через awg0 (ROUTE_SELF=1)
```

## Файлы

Бинарники в `bin/` кладет [get-bins.sh](../README.md) на компьютере.

| `bin/awg` | утилита настройки из amneziawg-tools, статическая сборка |

| `desc` | строка описания для панели |

| `/online/mod/conf/awg/split-direct.txt`, `split-vpn.txt` | свои исключения раздельного VPN |

| `/tmp/mod/awg/` | PID, журналы `svc.log` и `amneziawg-go.log`, состояние маршрутов (в ОЗУ, права 0700) |

## Команды

| команда | что делает |
|---|---|
| `svc.sh start` | запускает `amneziawg-go` с активным профилем, ставит адрес, маршруты и правила |
| `svc.sh stop` | снимает правила и маршруты, останавливает демон, удаляет `awg0` |
| `svc.sh restart` | `stop`, затем `start` |
| `svc.sh status` | печатает строки состояния, см. ниже |
| `svc.sh enable` | создает флаг автозапуска `enabled` |
| `svc.sh disable` | удаляет флаг автозапуска |
| `svc.sh profiles` | список профилей, см. ниже |
| `svc.sh list` | для меню экрана: строка на профиль `id\|подпись\|протокол\|активный` |
| `svc.sh brief` | для меню экрана: одна строка `running=0\|1\|profile=ИМЯ\|label=ПОДПИСЬ\|handshake=СЕКУНД\|engine=kernel\|go\|split=0\|1` |
| `svc.sh setconf ИМЯ [ПОДПИСЬ]` | читает конфиг со стандартного ввода и сохраняет профиль `ИМЯ` и подпись; без имени — активный профиль |
| `svc.sh use ИМЯ` | делает профиль активным; если туннель работал — перезапускает его с этим профилем. Выбор уже активного профиля при работающем туннеле ничего не делает |
| `svc.sh label ИМЯ ПОДПИСЬ` | меняет подпись профиля |
| `svc.sh delete ИМЯ` | удаляет профиль и его подпись; активный удалить нельзя |
| `svc.sh dns on\|off` | включает или выключает DNS клиентов через туннель: пишет `DNS_TUNNEL` в `settings` и применяет без перезапуска туннеля |
| `svc.sh dns` | печатает `dns=` и `dns_server=` |
| `svc.sh split on\|off` | раздельный VPN: включить или выключить без перезапуска туннеля; нет списка — код 1 |
| `svc.sh split-status` | строки `split=`, `split_active=`, `split_reason=`, `split_list=`, `split_prefixes=`, `split_date=`, `split_direct=`, `split_vpn=` |
| `svc.sh split-update ФАЙЛ` | проверяет и заменяет список российских адресов |
| `svc.sh split-direct add\|del\|list [АДРЕС]` | свои адреса и подсети «всегда напрямую» |
| `svc.sh split-vpn add\|del\|list [АДРЕС]` | свои адреса и подсети «всегда через VPN» |
| `svc.sh failover on [ИМЯ]\|off` | переключение профиля при обрыве; `ИМЯ` — основной профиль, по умолчанию активный |
| `svc.sh failover-status` | строки `failover=`, `failover_running=`, `failover_reason=`, `primary=` |

Код возврата: 0 — успех, 1 — ошибка; текст ошибки — одной строкой в stderr, без ключей. В выводе `list` и `brief` символ `|` в подписи заменен на `/`, `handshake=` пустой, если рукопожатия не было или туннель не запущен.

Первый сохраненный профиль становится активным. Если `setconf` перезаписал активный профиль при работающем туннеле, туннель перезапускается.

Имя профиля — техническое: строчные латинские буквы, цифры, `_` и `-`, до 32 символов. Пользователю показывается подпись: одна строка до 64 символов, любые буквы, без управляющих символов.
Если профилей нет, а в `/online/mod/conf/awg/` лежит старый `awg0.conf`, любая команда переносит его в профиль `awg2` и делает активным; файлы `ИМЯ.conf.saved` становятся профилями `ИМЯ`.
`setconf` проверяет, что в конфиге есть `[Interface]`, `PrivateKey`, `[Peer]`, `PublicKey`, `Endpoint`, и принимает не больше 64 КиБ.

Вывод `svc.sh profiles`, по пять строк на профиль:

| строка | что значит |
|---|---|
| `name=` | имя профиля |
| `label=` | подпись; если ее нет — имя |
| `active=0\|1` | профиль активный |
| `endpoint_host=` | адрес или имя сервера из `Endpoint`, без порта |
| `proto=` | версия по набору ключей: `3.1`, `3.0`, `2.0`, `1.0` или `wireguard` |

Вывод `svc.sh status`:

| строка | что значит |
|---|---|
| `running=0\|1` | демон работает и интерфейс `awg0` есть |
| `enabled=0\|1` | автозапуск включен |
| `info=…` | адрес, сервер, режим маршрутов, DNS клиентов, память демона |
| `rx=`, `tx=` | принято и отправлено через туннель, байт; пусто, если не запущен |
| `handshake=` | сколько секунд назад было последнее рукопожатие; пусто, если еще не было |
| `engine=kernel\|go` | что держит туннель: модуль ядра или `amneziawg-go`; пусто, если туннель не запущен |
| `engine_fallback=0\|1` | `1` — при `ENGINE=auto` модуль не сработал и туннель работает на `amneziawg-go` |
| `split=0\|1` | раздельный VPN включен настройкой; в `brief` `1` только при загруженном списке |
| `split_active=0\|1` | режим действует сейчас; при остановленном туннеле `0` |
| `split_reason=` | почему включенный режим не действует: `no_list`, `tunnel_down`, `no_full_tunnel`; иначе пусто |
| `split_list=0\|1` | список российских адресов загружен |
| `split_prefixes=`, `split_date=` | префиксов в списке и дата списка |
| `split_hint=` | совет про DNS, если режим действует, а DNS клиентов идет к оператору; иначе пусто |
| `failover=0\|1`, `primary=` | переключение при обрыве включено; основной профиль |
| `failover_running=0\|1` | цикл переключения работает |
| `failover_reason=` | последнее решение цикла, см. «Переключение при обрыве» |
| `profile=` | активный профиль |
| `profile_label=` | его подпись |
| `dns=tunnel\|operator\|dnspkg` | куда идут DNS-запросы клиентов LAN, см. «DNS клиентов»; пусто, если туннель не запущен |
| `dns_server=` | `tunnel` — адрес DNS в туннеле; `dnspkg` — серверы пакета `dns`, к которым стоят маршруты через туннель; иначе пусто |

Ключи в вывод `status`, `profiles`, `start` и `setconf` не попадают. Сообщения `awg` об ошибке в конфиге выводятся с заменой ключей на `***`.

## Конфиг туннеля

Подходит `.conf` из Amnezia VPN или с сервера AmneziaWG. `svc.sh` берет из него:

| ключ | что делает |
|---|---|
| `Address` | адреса интерфейса `awg0`; IPv6-адрес ставится, если ядро разрешает |
| `MTU` | MTU туннеля; нет ключа — `MTU_DEFAULT` |
| `DNS` | первый IPv4-адрес — DNS для клиентов LAN, если включен `DNS_TUNNEL` |
| `AllowedIPs` | `0.0.0.0/0` — весь трафик клиентов LAN в туннель; другие сети — маршрут в туннель для роутера и клиентов |

Остальное передается в `awg setconf`: ключи WireGuard и параметры маскировки всех версий.

| версия AmneziaWG | ключи |
|---|---|
| 1.0 | `Jc`, `Jmin`, `Jmax`, `S1`, `S2`, `H1`–`H4` |
| 2.0 | плюс `S3`, `S4`, `H1`–`H4` диапазоном (`100-200`), `I1`–`I5` |
| 3.0 | плюс `HeaderProtectionKey`, `ContentPaddingAddition`, `RekeyAfterTime`, `RekeyTimeout`, `RejectAfterTime`, `KeepaliveTimeout`, `MaxHandshakeAttempts`, `PersistentKeepalive` диапазоном |
| 3.1 | плюс `RandomTrailers`, `DisableCookies` |

Особые случаи:

- `RandomTrailers` и `DisableCookies` принимают `1`/`0` или `on`/`off`; `true` утилита `awg` не понимает.
- Ключи, которых нет в AmneziaWG 3.1 (например `J1` и `Itime` из пробной версии 1.5), `start` пропускает и называет в выводе.
- Ключи `awg-quick` для скриптов и таблиц (`Table`, `PreUp`, `PostUp`, `PreDown`, `PostDown`, `SaveConfig`) не выполняются.

## Настройки `conf`

В `conf` значения по умолчанию, установка новой версии его заменяет. `ENGINE`, `DNS_TUNNEL`, `SPLIT`, `FAILOVER` и `FAILOVER_PRIMARY` читаются поверх него из `/online/mod/conf/awg/settings`, строками `КЛЮЧ="значение"`: этот файл установка не трогает. `DNS_TUNNEL` пишет `svc.sh dns on\|off`.

| ключ | по умолчанию | что делает |
|---|---|---|
| `IFACE` | `awg0` | имя интерфейса туннеля |
| `CONF_DIR` | `/online/mod/conf/awg` | каталог профилей и файла `active` |
| `IFACE_LAN`, `IFACE_WAN` | `br0`, `eth_x` | интерфейсы LAN и мобильной сети |
| `ENGINE` | `auto` | `auto` — модуль, а если он не сработал — `amneziawg-go`; `kernel` — только модуль; `go` — только `amneziawg-go`. Если ключа нет — `go` |
| `MTU_DEFAULT` | `1280` | MTU, если в конфиге его нет |
| `ROUTE_SELF` | `0` | `1` — сам роутер тоже ходит в интернет через туннель |
| `KILLSWITCH` | `1` | если туннель упал, клиенты LAN не выходят в интернет напрямую |
| `DNS_TUNNEL` | `0` | DNS клиентов LAN через туннель; переключается `svc.sh dns on\|off` |
| `DNS_TUNNEL_SERVER` | `1.1.1.1` | DNS в туннеле, если в профиле нет `DNS` |
| `GO_GC` | `50` | сборщик мусора Go (`GOGC`): меньше — меньше памяти, больше работы процессора |
| `SPLIT` | `1` | раздельный VPN, действует при загруженном списке; переключается `svc.sh split on\|off` |
| `FAILOVER` | `1` | переключение профиля при обрыве, при одном профиле ничего не делает; переключается `svc.sh failover on\|off` |
| `FAILOVER_HS` | `180` | нет рукопожатия дольше стольких секунд — профиль считается неработающим |
| `FAILOVER_PAUSE` | `300` | пауза между переходами, с |
| `FAILOVER_RETRY` | `1800` | как часто с запасного профиля пробовать основной, с |
| `FAILOVER_POLL` | `30` | как часто проверять, с |
| `TABLE`, `PRIO` | `5300`, `5300` | таблица маршрутов и приоритеты `ip rule` (`PRIO` и `PRIO+1`) |

## Движок: модуль ядра или amneziawg-go

Модуля нет в этом каталоге. Лицензия модуля — GPL-2.0, поэтому он лежит вместе с исходниками, патчами и сборкой: `kernel-module/` рядом с `webui/` в общем комплекте для E5785Lh-23c.
Чтобы поставить модуль, на компьютере выполните:

```bash
src/pkg/get-bins.sh --only=awg --module
src/installer/install.sh --only=pkg --pkg-only=awg
```

Ключ берет вариант NEON: md5 `6650d98a006f25c1edf326693b81125a`, sha256 `f2b6991c0aa2895cd6b5e4c234cbf8732cff922ab8082ff999aad1101fc6afff`. Своя сборка модуля указывается так: `--module=ФАЙЛ`. Модуль работает только с ядром 3.10.100 этой прошивки.

Без файла пакет работает на `amneziawg-go`: это обычное состояние, подсказки о запасном пути в панели нет (`engine_fallback=0`). Если файл есть, но модуль не загрузился, `status` показывает `engine_fallback=1`, а панель — «Модуль ядра не загрузился, работает запасной путь».

Первый `start` записывает `5` в `/proc/sys/kernel/panic`: при панике роутер перезагрузится сам, а не зависнет. Значение действует до перезагрузки.
Затем `start` загружает модуль (около 1 с, идут самотесты шифров) и создает `awg0` через `ip link add`.

Если `insmod`, `ip link add` или `awg setconf` не сработали, при `ENGINE=auto` туннель поднимается на `amneziawg-go`. Причина попадает в `/tmp/mod/awg/svc.log` и в вывод `start`.

Внимание: модуль нельзя выгружать, `rmmod amneziawg` на работающем роутере вызывает панику ядра.
Каждый пакет туннеля несет ссылку на код модуля (деструктор `skb`) и может еще лежать в очереди модема. Когда модем освобождает такой пакет после выгрузки, ядро переходит на уже несуществующий адрес.

| действие | что происходит с модулем |
|---|---|
| `svc.sh stop`, `svc.sh use` | удаляется только `awg0`, модуль остается загруженным |
| переход на `ENGINE=go` | `svc.sh restart`: удаляется `awg0`, модуль остается загруженным и не мешает |
| откат или удаление пакета | файл `amneziawg.ko` удаляется, загруженный модуль остается до перезагрузки |
| убрать модуль совсем | только перезагрузка роутера |

## Правила и маршруты

Все правила — в своих цепочках, `stop` снимает их целиком, удаляет правила `ip rule`, таблицу `TABLE` и добавленные маршруты.

| что | где | когда | что делает |
|---|---|---|---|
| `ip rule` `PRIO` | — | весь трафик в туннель | клиенты LAN к сети LAN (192.168.1.0/24) — по таблице `main` |
| `ip rule` `PRIO+1`, таблица `TABLE` | — | весь трафик в туннель | остальной трафик клиентов LAN — в `awg0`; при `KILLSWITCH=1` запасной маршрут `unreachable` |
| `MOD_AWG_NAT` | `nat POSTROUTING -o awg0` | всегда | MASQUERADE клиентов в туннель |
| `MOD_AWG_MSS` | `mangle FORWARD`, `-i/-o awg0` | всегда | MSS TCP — под MTU туннеля |
| `MOD_AWG_KS` | `filter FORWARD -i br0 -o eth_x` | `KILLSWITCH=1`, весь трафик | отказ: клиенты LAN не идут к оператору напрямую |
| `MOD_AWG6` | `ip6tables filter FORWARD -i br0 -o eth_x` | весь трафик | отказ для IPv6 клиентов: в туннель IPv6 не идет, без отказа была бы утечка |
| `MOD_AWG_DNS` | `nat PREROUTING -i br0` | `DNS_TUNNEL=1`, пакет `dns` не запущен | DNS клиентов (порт 53) — на `DNS` профиля или `DNS_TUNNEL_SERVER` |
| `MOD_AWG_DNS6` | `ip6tables filter INPUT -i br0` | то же | отказ на DNS роутера по IPv6: там отвечает DNS оператора |
| маршруты к серверам пакета `dns` | `main`, `dev awg0` | `DNS_TUNNEL=1`, пакет `dns` запущен в режиме `secure` | его запросы DoH и DoT идут через туннель |
| маршрут к серверу | `main`, через шлюз `eth_x` | `ROUTE_SELF=1` или сети `/1` в `AllowedIPs` | пакеты туннеля не уходят в сам туннель |

Управление роутером по USB и Wi-Fi (сеть LAN, адрес 192.168.1.1) в туннель не уходит: правило `PRIO` и локальная таблица маршрутов стоят раньше.
Сеть LAN в `AllowedIPs` пропускается.
Правило мода `TTL --ttl-set 64` действует на внешние пакеты туннеля, как на весь трафик роутера; пакеты внутри туннеля оператор не видит.

## DNS клиентов

Клиенты LAN по умолчанию спрашивают DNS у роутера, а он — у оператора. DNS Tele2 подменяет ответы для заблокированных сайтов
(например `127.0.0.2`), поэтому без `DNS_TUNNEL` такие сайты не откроются и через туннель.

| `DNS_TUNNEL` | что запущено | куда идут DNS-запросы клиентов LAN | `dns=` |
|---|---|---|---|
| `0` | только `awg` | DNS оператора мимо туннеля | `operator` |
| `1` | только `awg` | `DNS` профиля, а если его нет — `DNS_TUNNEL_SERVER`, через туннель | `tunnel` |
| `0` или `1` | пакет `dns` | dnsmasq на роутере; при `1` его серверы DoH и DoT — через туннель | `dnspkg` |

`DNS_TUNNEL` действует, только если в туннель идет весь трафик (`AllowedIPs = 0.0.0.0/0`).
Если пакет `dns` запустили или остановили вручную при работающем туннеле, выполните `svc.sh dns on`, чтобы пересчитать маршруты. При запуске туннеля пакет `dns` поднимается раньше правил, отдельной команды не нужно.

## Раздельный VPN

Российские адреса идут напрямую через оператора, остальное через туннель. По умолчанию включено, но действует только при загруженном списке. Без списка клиенты работают как при обычном полном VPN: весь трафик в туннеле, защита от утечки на месте, `split_reason=no_list`, `start` проходит без ошибок. Появился список — режим включается сразу, без перезапуска туннеля. Трафик самого роутера не меняется: при `ROUTE_SELF=0` он идет напрямую, а при `ROUTE_SELF=1` — через туннель целиком, список на него не действует. Режим работает, только если в туннель идет весь трафик (`AllowedIPs = 0.0.0.0/0`).

Сайт на зарубежном адресе или CDN идет через туннель. Сайт на российском адресе идет напрямую, и блокировка оператора для него остается.

Списка в пакете нет: это производные данные RIPE NCC, условия RIPE не дают их распространять. Получите его сами, подробнее — [tools/README.md](tools/README.md):

1. На компьютере скачайте файл статистики RIPE NCC:

   ```bash
   curl -O https://ftp.ripe.net/pub/stats/ripencc/delegated-ripencc-extended-latest
   ```

2. Соберите список:

   ```bash
   python3 src/pkg/awg/tools/split-gen.py delegated-ripencc-extended-latest ru-list.txt
   ```

3. Загрузите файл на роутер кнопкой «Загрузить файл» на странице VPN или командой `svc.sh split-update ФАЙЛ`.
4. Включите режим: `svc.sh split on`. Без списка команда вернет код 1 и строку «нет списка российских адресов: загрузите файл».

Список обновляется только этими шагами, сам роутер его не скачивает. Включение и выключение не трогают уже открытые соединения: они могут оборваться и открыться заново.

Если туннель упал при `KILLSWITCH=1`, российские адреса работают напрямую, а зарубежные недоступны. Правила `MOD_AWG_KS` в этом режиме нет, защиту держит `unreachable` в таблице туннеля.

Исключения — только адреса и подсети, длина от 8 до 32. Домены не поддерживаются: в ядре нет ipset.

| DNS при включенном режиме | что будет |
|---|---|
| только раздельный VPN | DNS оператора: заблокированные зарубежные сайты получают подмену и не открываются даже через туннель |
| пакет `dns`, пресет `auto` | рекомендуется: DoT напрямую, подмены нет, российские адреса отдаются как обычно |
| `svc.sh dns on` | ответы для точки выхода VPN: российский сайт на CDN может получить зарубежный адрес и пойти через туннель |

Запуск туннеля сам поднимает пакет `dns`, если пользователь его не выключил: см. README пакета `dns`, раздел «VPN включен, DNS тоже». Без списка российских адресов правило то же.

## Переключение при обрыве

По умолчанию включено. Цикл идет, только если `FAILOVER=1`, туннель запущен и профилей хотя бы два; `stop` его останавливает, `start` запускает снова. При одном профиле цикла нет и в журнал ничего не пишется, `failover_reason=no_other_profile`; второй профиль запускает цикл сам, `failover on` при одном профиле вернет код 1. В туннеле не на весь трафик цикл ничего не переключает, `failover_reason=no_full_tunnel`: пробный пакет к 1.1.1.1 не вызвал бы рукопожатия.

1. Нет рукопожатия дольше `FAILOVER_HS`: цикл шлет пробный `ping` через туннель, ведь без трафика рукопожатий может просто не быть.
2. Рукопожатия все равно нет: цикл проверяет сеть оператора TCP-соединением с 77.88.8.8 и 1.1.1.1 через `eth_x`.
3. Сеть оператора лежит: профили не перебираются.
4. Сеть есть и прошла пауза `FAILOVER_PAUSE`: переход на следующий профиль по кругу. Модуль не выгружается.
5. На запасном профиле раз в `FAILOVER_RETRY` цикл пробует основной. Проба — короткий простой туннеля: основной нельзя проверить, не переключившись на него. Если он не ответил, цикл возвращается на запасной.

Выбор профиля пользователем командой `use` делает этот профиль основным.

| `failover_reason=` | что значит |
|---|---|
| `ok` | работает основной профиль |
| `on_backup` | работает запасной, основной еще не пробовали |
| `switched` | только что перешли на следующий профиль |
| `returned_primary` | основной снова отвечает, вернулись на него |
| `primary_still_down` | проба основного не удалась, вернулись на запасной |
| `operator_down` | рукопожатия нет, сеть оператора тоже недоступна, профили не перебираются |
| `pause` | рукопожатия нет, ждем паузу между переходами |
| `no_other_profile` | профиль один, переключаться не на что; цикла нет |
| `no_full_tunnel` | в туннель идет не весь трафик, цикл ничего не переключает |
| `tunnel_down` | туннель не запущен |

## Проверка

```sh
/online/mod/pkg/awg/svc.sh setconf home < home.conf
/online/mod/pkg/awg/svc.sh use home
/online/mod/pkg/awg/svc.sh start
/online/mod/pkg/awg/svc.sh status
ip rule list
```

Ожидаемо: `running=1`, `engine=kernel` или `engine=go` без файла модуля, `handshake=` — небольшое число секунд, в `ip rule list` — строки `5300` и `5301`.

## Ограничения

- IPv6 клиентов LAN в туннель не идет: в ядре нет NAT для IPv6. При полном туннеле IPv6 клиентам отключается.
- Предел туннеля — 41–46 Мбит/с на 4–8 соединениях, упор в процессор (87–99 %). Напрямую тот же сервер отдает 105 Мбит/с на 4 соединениях.
- Одно соединение через туннель — обычно 7–12 Мбит/с, зависит от задержки и разгона TCP. Что именно держит окно TCP, не установлено; увеличение `tcp_rmem` до 8 МБ заметного выигрыша не дает. На близком сервере больше: Cloudflare около 22 Мбит/с.
- Эти цифры сняты на самом роутере. С устройства в сети роутера предел не измерен.
- `amneziawg-go` занимает около 4 МиБ ОЗУ в покое и 8–9 МиБ под нагрузкой при `GO_GC=50` (до 17 МиБ при `GO_GC=100`).
- Модуль занимает 167 КиБ и не держит процесса в ОЗУ. Загруженный модуль нельзя заменить новой версией без перезагрузки.
- Модуль собран для этого ядра 3.10.100 и этой прошивки. Он проверен на одном роутере, переход на него — на ваш риск: ошибка в модуле приводит к панике и перезагрузке.
- При `ROUTE_SELF=1` маршрут к серверу идет через текущий шлюз оператора. Если шлюз сменится при переподключении сети, выполните `svc.sh restart`.
- Конфиг с именем сервера вместо адреса (`Endpoint = vpn.example.com:51820`) разрешается через стоковый DNS роутера при запуске.
