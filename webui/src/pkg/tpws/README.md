# tpws: обход DPI через прозрачный прокси

tpws принимает TCP-соединения клиентов LAN к портам 80 и 443 и сам открывает их к сайту.
Запрос клиента (HTTP или TLS ClientHello) tpws отправляет кусками, чтобы DPI оператора не узнал имя сайта.
Для TLS по умолчанию: две TLS-записи с границей перед SNI, разрез на 1-м байте и в середине домена, байт срочных данных.
Программа из проекта zapret (bol-van/zapret, v72.13, готовый бинарник `linux-arm` из релиза).

```text
клиент LAN ──TCP 80/443──► br0 ── nat PREROUTING ─► MOD_TPWS ─► REDIRECT :988
                                                                  │
                                       tpws (192.168.1.1:988) ◄───┘
                                         └─► сайт, запрос разрезан на части
клиент LAN ──UDP 443 (QUIC)──► filter FORWARD ─► MOD_TPWS_QUIC ─► отказ (если BLOCK_QUIC=1)
```

## Файлы

Бинарник в `bin/` кладет [get-bins.sh](../README.md) на компьютере.

| файл | что это |
|---|---|
| `bin/tpws` | программа, статическая ARM, сжата UPX |
| `svc.sh` | запуск, остановка, состояние, автозапуск |
| `conf` | настройки |
| `enabled` | флаг автозапуска: есть файл — общий автозапуск выполняет `svc.sh start` |
| `/tmp/mod/tpws/` | PID, журнал запуска, копия списка доменов (в ОЗУ, после перезагрузки пусто) |

## Команды

| команда | что делает |
|---|---|
| `svc.sh start` | запускает tpws и ставит правила iptables |
| `svc.sh stop` | снимает правила и останавливает tpws |
| `svc.sh restart` | `stop`, затем `start` |
| `svc.sh status` | печатает `running=0\|1`, `enabled=0\|1`, `info=…` |
| `svc.sh enable` | создает флаг автозапуска `enabled` |
| `svc.sh disable` | удаляет флаг автозапуска |

## Настройки `conf`

| ключ | по умолчанию | что делает |
|---|---|---|
| `IFACE_LAN` | `br0` | интерфейс клиентов |
| `IFACE_WAN` | `eth_x` | внешний интерфейс, для правила TTL |
| `PORT` | `988` | порт tpws на адресе `br0` |
| `PORTS` | `80,443` | порты сайтов, соединения к которым идут через tpws |
| `TPWS_OPT` | см. файл | стратегия: параметры tpws, профили разделяет `--new` |
| `BLOCK_QUIC` | `1` | запрет QUIC (UDP 443), чтобы браузер перешел на TCP |
| `HOSTLIST` | пусто | файл со списком доменов; пусто — обход для всех сайтов |
| `RUN_UID` | `65534:3003` | пользователь и группа tpws после запуска |
| `NOFILE` | `4096` | предел открытых файлов |

Группа 3003 (`inet`) в `RUN_UID` обязательна. Ядро роутера дает сетевые сокеты только root и этой группе.
Без нее tpws принимает соединение, но не может открыть его к сайту.

## Правила iptables

Все правила — в своих цепочках, `stop` снимает их целиком.

| таблица | цепочка | откуда переход | что делает |
|---|---|---|---|
| `nat` | `MOD_TPWS` | `PREROUTING`, первым, `-i br0 -p tcp` | частные сети пропускает, порты `PORTS` переводит на tpws |
| `filter` | `MOD_TPWS_QUIC` | `FORWARD`, первым, `-i br0 -p udp` | отказ для UDP 443 |
| `mangle` | `MOD_TPWS_TTL` | `OUTPUT`, первым, `-o eth_x` | пакеты с TTL 1 — мимо правила мода `TTL --ttl-set 64` |

При `--disorder` tpws шлет части запроса с TTL 1, чтобы они пропали и пришли повторно позже.
Правило мода `TTL --ttl-set 64` переписало бы TTL, поэтому `MOD_TPWS_TTL` пропускает такие пакеты раньше него.

## Проверка

```sh
/online/mod/pkg/tpws/svc.sh start
/online/mod/pkg/tpws/svc.sh status
iptables -t nat -S MOD_TPWS
```

Ожидаемо: `running=1`, в `info` — `правила: есть`, в `netstat -lnt` — `192.168.1.1:988`.

## Ограничения

- Только IPv4: в ядре роутера нет NAT для IPv6, перенаправить IPv6-соединения нельзя.
- Только TCP. QUIC (UDP 443) tpws не обрабатывает, его можно только запретить.
- Не помогает, если сайт заблокирован по IP-адресу или если DNS оператора выдает неверный адрес. Для DNS — пакет `dns`.
- Не помогает против обрыва соединений с зарубежными хостингами после первых 15–20 КиБ (так описывают пользователи): этот блок не зависит от имени сайта.
- Стратегия по умолчанию подходит не всем операторам. Подбор — `blockcheck.sh` из zapret на компьютере.
- tpws в zapret не развивается, выходят только исправления ошибок. Обход надежнее у пакета `zapret2`.
- Не включайте вместе с пакетом `zapret2`: соединения tpws выходят с роутера и второй раз попадают в nfqws2.
