# zapret2: обход DPI подменой первых пакетов

nfqws2 получает из ядра первые пакеты каждого соединения к портам 80 и 443 (TCP) и 443 (UDP, QUIC).
Перед настоящим запросом он отправляет поддельный, который сайт отбрасывает, а настоящий режет и переставляет.
DPI оператора видит подделку или не может собрать имя сайта.
Программа из проекта zapret2 (bol-van/zapret2, v1.0.6, готовый бинарник `linux-arm` из релиза), стратегии — на Lua.

```text
клиент LAN ─► FORWARD ─► mangle POSTROUTING: … правило TTL мода … ─► MOD_ZAP2_OUT ─► NFQUEUE 200 ─► nfqws2
сайт ───────► mangle PREROUTING ─► MOD_ZAP2_IN ─► NFQUEUE 200 ─► nfqws2      (первые пакеты ответа)
nfqws2 ─► свои пакеты с битом 0x40000000 ─► MOD_ZAP2_SKIP (OUTPUT, POSTROUTING) ─► ACCEPT, мимо TTL мода
```

## Файлы

Бинарник в `bin/` и файлы в `lua/` кладет [get-bins.sh](../README.md) на компьютере.

| файл | что это |
|---|---|
| `bin/nfqws2` | программа, статическая ARM, LuaJIT внутри, сжата UPX |
| `lua/zapret-lib.lua`, `lua/zapret-antidpi.lua` | библиотека и стратегии на Lua из релиза |
| `svc.sh` | запуск, остановка, состояние, автозапуск |
| `conf` | настройки |
| `enabled` | флаг автозапуска: есть файл — общий автозапуск выполняет `svc.sh start` |
| `/tmp/mod/zapret2/` | PID, журнал запуска, копии Lua и списка доменов (в ОЗУ) |

## Команды

| команда | что делает |
|---|---|
| `svc.sh start` | запускает nfqws2 и ставит правила iptables и ip6tables |
| `svc.sh stop` | снимает правила и останавливает nfqws2 |
| `svc.sh restart` | `stop`, затем `start` |
| `svc.sh status` | печатает `running=0\|1`, `enabled=0\|1`, `info=…` |
| `svc.sh enable` | создает флаг автозапуска `enabled` |
| `svc.sh disable` | удаляет флаг автозапуска |

## Настройки `conf`

| ключ | по умолчанию | что делает |
|---|---|---|
| `IFACE_WAN` | `eth_x` | внешний интерфейс |
| `QNUM` | `200` | номер очереди NFQUEUE |
| `FWMARK` | `0x40000000` | бит mark на пакетах nfqws2 |
| `PORTS_TCP`, `PORTS_UDP` | `80,443`, `443` | порты сайтов, пакеты к которым идут в nfqws2 |
| `TCP_PKT_OUT`, `TCP_PKT_IN` | `9`, `3` | сколько первых пакетов TCP-соединения отдавать в nfqws2: к сайту и от сайта |
| `UDP_PKT_OUT`, `UDP_PKT_IN` | `5`, `3` | то же для UDP |
| `IPV6` | `1` | ставить правила и для IPv6 |
| `NFQWS2_OPT` | см. файл | стратегия: параметры nfqws2, профили разделяет `--new` |
| `HOSTLIST` | пусто | файл со списком доменов; пусто — обход для всех сайтов |
| `RUN_UID` | `2147483647:3003,3004` | пользователь и группы nfqws2 после запуска |

После запуска nfqws2 работает не от root и не видит `/online`.
Поэтому `svc.sh` копирует Lua и список доменов в `/tmp/mod/zapret2/`.
Группы 3003 (`inet`) и 3004 (`net_raw`) нужны, потому что ядро роутера дает сетевые сокеты только root и этим группам.

## Правила iptables

Правила одинаковые для `iptables` и `ip6tables` (если `IPV6=1`), все — в таблице `mangle`, в своих цепочках.
`stop` снимает их целиком.

| цепочка | откуда переход | что делает |
|---|---|---|
| `MOD_ZAP2_SKIP` | `OUTPUT` и `POSTROUTING`, первым | пакеты nfqws2 (бит `FWMARK`) — `ACCEPT` |
| `MOD_ZAP2_OUT` | `POSTROUTING`, последним, `-o eth_x` | первые `*_PKT_OUT` пакетов соединения к портам сайтов — в очередь |
| `MOD_ZAP2_IN` | `PREROUTING`, первым, `-i eth_x` | первые `*_PKT_IN` пакетов ответа — в очередь |

В ядре роутера нет `connbytes`, которым zapret2 обычно отбирает первые пакеты.
Вместо него — `hashlimit` по адресам и портам соединения: запас N пакетов, дальше один пакет в час.
Пакеты с флагом SYN в очередь не идут: так они проходят стоковые правила `TCPMSS`, которые стоят в `mangle` позже.

Мод ставит в `mangle` правило `TTL --ttl-set 64` для `eth_x`. Переход в `MOD_ZAP2_OUT` стоит после него,
поэтому настоящий пакет уходит с TTL 64. Свои пакеты nfqws2 проходят `MOD_ZAP2_SKIP` раньше правила TTL и сохраняют TTL, заданный стратегией.

## Проверка

```sh
/online/mod/pkg/zapret2/svc.sh start
/online/mod/pkg/zapret2/svc.sh status
iptables -t mangle -L MOD_ZAP2_OUT -n -v
```

Ожидаемо: `running=1`, в `info` — `правила: есть`; счетчики пакетов в `MOD_ZAP2_OUT` растут, когда клиенты открывают сайты.

## Ограничения

- На проходящем трафике iptables отдает пакеты в nfqws2 до NAT. Стратегии, которые ломают NAT, не работают.
- В ядре нет seccomp: nfqws2 пишет предупреждение и работает без этой защиты.
- Таблица `hashlimit` рассчитана на 16384 соединения. Если соединений больше, ядро может отбрасывать новые пакеты к портам `PORTS_*`.
- Не помогает, если сайт заблокирован по IP-адресу или DNS оператора выдает неверный адрес. Для DNS — пакет `dns`.
- Стратегия по умолчанию подходит не всем операторам. Подбор — `blockcheck2.sh` из zapret2 на компьютере.
- Аппаратное ускорение пересылки пакетов (SPE) в моде выключено (`/system/etc/disable_spe` = 1). Если его включить, проходящий трафик, судя по скрипту TTL мода, пойдет мимо iptables, и обход перестанет действовать (не проверено).
- Не включайте вместе с пакетом `tpws`: соединения tpws выходят с роутера и второй раз попадают в nfqws2.
