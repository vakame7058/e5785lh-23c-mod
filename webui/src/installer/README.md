# Установщик веб-панели E5785Lh-23c

Ставит на роутер одностраничный веб-интерфейс (SPA), обработчики `/api/mod/*`, помощник и пакеты одной командой с компьютера
и так же одной командой все возвращает. Для того, кто ставит и обновляет панель.
Обзор и требования — [README.md](../../README.md), вызовы API — [docs/API.md](../../docs/API.md).

## Установка

На компьютере, роутер подключен по USB (адрес `192.168.1.1`). Бинарники пакетов уже получены: `src/pkg/get-bins.sh`,
см. [src/pkg/README.md](../pkg/README.md).

```bash
cd src/installer
./install.sh --dry-run      # что изменится на роутере, ничего не меняет
./install.sh                # установка
```

`install.sh` собирает SPA (`build.py` фронтенда), берет `src/backend` и `src/pkg`, упаковывает
в tar и передает по SSH. Перед любым обращением к роутеру `install.sh` и `rollback.sh` проверяют
две вещи и при сбое отказываются, ничего не отправив:

- маршрут к `192.168.1.1` идет через `wwx001e101f0000` (`ip route get 192.168.1.1`);
- ключ хоста SSH совпадает с файлом ключей хостов (`StrictHostKeyChecking=yes`, имя хоста в файле — `e5785-router`).

Без этих проверок при пропавшей сети по USB адрес `192.168.1.1` уходит по маршруту по умолчанию,
и отвечает другое устройство.

На роутере `mod-install.sh`:

1. Проверяет пути в пакете и свободное место на каждом разделе.
2. Сохраняет заменяемые файлы и список новых в `/online/mod/bak/install-ВРЕМЯ/`.
3. Останавливает помощник и пакеты, если их файлы есть в пакете.
4. Перемонтирует разделы на запись, копирует, сверяет каждый файл с пакетом.
5. Возвращает разделы в «только чтение».
6. Запускает помощник и включенные пакеты.

Если запись прервалась на середине, файлы возвращаются из сохраненной копии автоматически.
После установки `install.sh` проверяет с компьютера, что `/` отдает SPA, `/js/mod/app.js`
и `/css/mod/app.css` совпадают со сборкой, стоковый `/html/index.html` открывается,
а `/api/mod/sysinfo` без входа отвечает «нужен вход» (код `100003`).

Обновление — та же команда `./install.sh`. Каждая установка заводит свою запись для отката.

| ключ `install.sh` | что делает |
|---|---|
| `--dry-run` | собрать пакет и показать список файлов, место и разделы; ничего не менять |
| `--only=web,api,pkg` | ставить только перечисленные части (по умолчанию все три) |
| `--dist=КАТАЛОГ` | готовая сборка SPA вместо `src/frontend/dist`, `build.py` не запускается |
| `--no-build` | взять `src/frontend/dist` как есть |
| `--backend=КАТАЛОГ` | вместо `src/backend` (в нем `api/mod/` и `helper/`) |
| `--pkg=КАТАЛОГ` | вместо `src/pkg` (каталог на каждый пакет) |
| `--check-api=ИМЯ` | обработчик для проверки «нужен вход», по умолчанию `sysinfo` |
| `--save=ФАЙЛ` | только собрать пакет в tar, на роутер не ходить |
| `--host=АДРЕС` | адрес роутера, по умолчанию `192.168.1.1` |
| `--iface=ИМЯ` | интерфейс компьютера к роутеру, по умолчанию `wwx001e101f0000` |
| `--via=jump` | через другой компьютер в сети роутера, вместе с `--jump` и `--jump-iface`; есть и у `rollback.sh` |
| `--jump=ИМЯ` | этот компьютер: имя из `~/.ssh/config` |
| `--jump-iface=ИМЯ` | его интерфейс в сети роутера: маршрут к роутеру на нем должен идти через этот интерфейс |
| `--pkg-only=ИМЯ,ИМЯ` | ставить только эти пакеты, например `--only=pkg --pkg-only=awg`: на `/online` мало места на все сразу |

Ключ SSH и файл ключей хостов задают переменные `ROUTER_KEY` и `ROUTER_KNOWN_HOSTS`: по умолчанию ключи `ssh` и `~/.ssh/known_hosts`.

| часть | что входит |
|---|---|
| `web` | `dist/html/mod.html`, `dist/js/mod/*`, `dist/css/mod/*` |
| `api` | `src/backend/api/mod/*` и `src/backend/helper/*`, автозапуск |
| `pkg` | `src/pkg/ИМЯ/*` для каждого пакета, автозапуск |

## Откат

```bash
./rollback.sh --dry-run     # что будет сделано
./rollback.sh               # отменить все установки, вернуть роутер к состоянию до первой
./rollback.sh --last        # отменить только последнюю установку (вернуть предыдущую версию)
```

Откат идет по записям `/online/mod/bak/install-*` от последней к первой:

1. Если отменяемые установки ставили помощник или пакеты — останавливает их
   и снимает все цепочки iptables `MOD_*`.
2. Удаляет файлы, которых до установки не было, и созданные установкой каталоги.
3. Возвращает замененные файлы из копии: содержимое, права, владелец, время изменения.
4. Возвращает разделы в «только чтение».

Отмененные записи переносятся в `/online/mod/bak/undone/`. Откат не трогает `/online/scripts`,
`/online/modwebui_backup.tar`, `/online/atp_backup`, перехватчики экрана, стоковые файлы вне списка
ниже. Без компьютера то же самое делает команда на роутере:

```bash
busyboxx sh /online/mod/mod-uninstall.sh [--last] [--dry-run]
```

## Что меняется на роутере

| путь | раздел | что это |
|---|---|---|
| `/app/html/redirect.html` | `/app`, `mtdblock24` | оболочка SPA, отдается на корень сайта `/`; стоковый файл заменяется, копия — в записи отката |
| `/app/webroot/WebApp/common/js/mod/` | `/app/webroot`, `mtdblock25` | `app.js.gz` и прочие файлы SPA; `index.html.gz` — запасной адрес оболочки `/js/mod/index.html` |
| `/app/webroot/WebApp/common/css/mod/` | `/app/webroot`, `mtdblock25` | `app.css.gz` |
| `/app/html/api/mod/` | `/app`, `mtdblock24` | обработчики Lua `/api/mod/ИМЯ` |
| `/system/etc/autorun.d/mod.sh` | `/system`, `mtdblock26` | автозапуск помощника и пакетов |
| `/online/mod/helper/` | `/online` | помощник; обработчик `h` из исходников ложится в `www/cgi-bin/h` |
| `/online/mod/pkg/ИМЯ/` | `/online` | пакеты |
| `/online/mod/mod-ctl.sh`, `mod-lib.sh`, `mod-uninstall.sh`, `VERSION` | `/online` | запуск и остановка, откат, что установлено |
| `/online/mod/bak/install-ВРЕМЯ/` | `/online` | запись для отката: `saved.tar`, `new.list`, `replaced.list`, `newdirs.list`, `dirmodes.list` |

Писать за пределами этих путей установщик отказывается до начала записи.
Каталоги `/online/mod`, `helper`, `pkg` получают владельца root и права `755`: помощник работает
от root, а веб-сервер (uid 1000) не должен иметь права менять его файлы. Прежние права каталогов
откат возвращает.
Сам `/online` принадлежит uid 1000, поэтому процесс с этим uid может подменить `/online/mod` и получить root.

Файлы установщика:

| файл | где работает | что делает |
|---|---|---|
| `install.sh` | компьютер | сборка пакета, передача, проверка после установки |
| `rollback.sh` | компьютер | откат |
| `host-lib.sh` | компьютер | общее: проверка маршрута и ключа хоста перед обращением к роутеру |
| `router/mod-install.sh` | роутер | установка из пакета |
| `router/mod-uninstall.sh` | роутер | откат по записям |
| `router/mod-ctl.sh` | роутер | `start`, `stop`, `restart`, `status`, `boot` для помощника и пакетов; `seed-save` сохраняет запас случайности |
| `router/mod-lib.sh` | роутер | общие функции: разрешенные пути, разделы, PID-файлы, цепочки |
| `router/autorun-mod.sh` | роутер | ставится как `/system/etc/autorun.d/mod.sh` |
| `host/e5785-usbnet.service` | компьютер | адрес компьютера в сети по USB, см. ниже |

## Как роутер отдает SPA

| адрес | файл на роутере | как отдается |
|---|---|---|
| `/` | `/app/html/redirect.html` | `text/html`, веб-сервер вставляет после `<head>` два `<meta name="csrf_token">` |
| `/js/mod/app.js` | `WebApp/common/js/mod/app.js.gz` | `Content-Encoding: gzip` |
| `/css/mod/app.css` | `WebApp/common/css/mod/app.css.gz` | `Content-Encoding: gzip` |
| `/js/mod/index.html` | `WebApp/common/js/mod/index.html.gz` | как `/`, распакованным |
| `/html/index.html` | стоковый | не меняется |

- `/js/**` и `/css/**` отдаются по маске: веб-сервер ищет `X`, затем `X.gz`. Если есть оба, отдает `X`.
  Поэтому установщик кладет только `.gz`.
- `.gz` отдается с `Content-Encoding: gzip` даже клиенту, который сжатие не просил.
- Кэша нет: все ответы с `Cache-Control: no-cache, no-store`, страница каждый раз загружается заново.
- Страницы `/html/*.html` отдаются только из подписанного списка `/app/webauth/htmlconfig.xml`,
  остальные уводят на `/html/index.html` (код 307). Подпись не дает добавить в список `/html/mod.html`,
  поэтому оболочка SPA отдается на корень `/`.
- Пути в оболочке должны быть абсолютными: `/js/mod/app.js`, `/css/mod/app.css`.
- Правка `/app/html/redirect.html` действует сразу, перезапуск веб-сервера не нужен.

## Помощник, пакеты, автозапуск

Автозапуск `/system/etc/autorun.d/mod.sh` вызывает `/system/etc/autorun.sh` при загрузке, до запуска
веб-сервера, и ждет его завершения. Поэтому `mod.sh` только запускает в фоне
`/online/mod/mod-ctl.sh boot` и сразу выходит: ошибка или зависание помощника загрузку не задерживают.
`mod-ctl.sh boot` подмешивает запас случайности, ждет процесс `web` (до 180 с), затем запускает помощник и включенные пакеты.

| что | договор |
|---|---|
| помощник | `/online/mod/helper/start.sh boot\|start\|stop\|status` |
| пакет | каталог `/online/mod/pkg/ИМЯ/` со скриптом `svc.sh start\|stop` |
| пакет включен | есть файл `/online/mod/pkg/ИМЯ/enabled`; в пакет установщика этот файл не попадает |
| PID-файлы | `/var/run/mod/*.pid`, `/tmp/mod/*/*.pid`, `/var/modhelper/*.pid` |
| запас случайности | `/online/mod/conf/random-seed` (512 байт, 0600), только на роутере. Есть при загрузке: подмешивается в `/dev/urandom`, `/dev/random` заменяется на `/dev/urandom` (`mount -o bind`). Записывается при установке (если роутер работает от 5 минут), при загрузке и через 12 минут работы. Откат: `mod-uninstall.sh` удаляет файл и снимает замену |
| остановка по PID-файлу | только процесс, в командной строке которого есть `/online/mod/` |
| правила iptables | только в своих цепочках `MOD_*`; откат снимает переходы в них и сами цепочки |
| время на `start` и `stop` | 30 и 20 с на скрипт, дольше — прерывается |
| журнал запуска | `/tmp/mod-ctl.log` (в ОЗУ, до 64 КиБ) |

Выключить автозапуск, не удаляя установку: на роутере `busyboxx touch /online/mod/disabled`.
Включить снова: `busyboxx rm /online/mod/disabled`.

## Адрес компьютера в сети по USB

После перезагрузки роутера интерфейс `wwx001e101f0000` появляется заново выключенным и без адреса.
NetworkManager этот интерфейс не берет: для него это модем (`DEVTYPE=wwan`), а такими он управляет
только через ModemManager. ModemManager не запускайте: он начнет слать команды в порт модема роутера.
Вместо этого — юнит systemd, который срабатывает при появлении интерфейса.

Установка (на компьютере, один раз):

```bash
sudo install -m 644 src/installer/host/e5785-usbnet.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now e5785-usbnet.service
```

Проверка:

```bash
systemctl status e5785-usbnet.service
ip -br addr show wwx001e101f0000    # ожидается UP или UNKNOWN и 192.168.1.200/24
ip route get 192.168.1.1            # ожидается dev wwx001e101f0000
ip route show default               # маршрут по умолчанию прежний
```

Юнит ставит только адрес `192.168.1.200/24`: маршрут по умолчанию и DNS не меняются.
Удаление:

```bash
sudo systemctl disable --now e5785-usbnet.service
sudo rm /etc/systemd/system/e5785-usbnet.service
sudo systemctl daemon-reload
```

## Неполадки

| признак | причина | что сделать |
|---|---|---|
| «маршрут к 192.168.1.1 идет через «ИМЯ», а не через wwx001e101f0000» | нет сети по USB, адрес ушел по маршруту по умолчанию к другому устройству | `ip -br addr show wwx001e101f0000`; если интерфейса нет, смотреть `lsusb` |
| «SSH до 192.168.1.1 не прошел или ключ хоста не совпал» | роутер не отвечает по SSH, ключа хоста еще нет в файле или по адресу другое устройство | проверить маршрут и роутер; первое подключение — как в [README.md](../../README.md); записанный ключ не менять, пока не ясно, кто отвечает |
| интерфейса `wwx001e101f0000` нет, `lsusb` показывает `12d1:1c20` или `12d1:15ca` | роутер в другом режиме USB | переключение режима — вне установщика; юнит сработает, когда интерфейс появится |
| «есть незавершенная установка» | установка прервалась (обрыв связи, перезагрузка) | `./rollback.sh`, затем установка заново |
| «НЕ ХВАТАЕТ» в таблице места | на разделе меньше места, чем нужно, плюс запас 256 КиБ | освободить место или ставить по частям `--only=` |
| «занят и остался на запись» | раздел нельзя перемонтировать, пока на нем открыт файл на запись | вернется в «только чтение» после перезагрузки |
| «каталог не пуст, оставлен» при откате | в каталоге есть файлы, которые положил не установщик | проверить содержимое каталога вручную |
| `/` показывает стоковый интерфейс после установки | заменен `/app/html/redirect.html` чем-то другим | `./install.sh --only=web` |
| помощник или пакет не запустился | ошибка в его скрипте | `busyboxx cat /tmp/mod-ctl.log` на роутере |

## Ограничения

- Установщик не меняет подписанные `/app/webauth/*.xml`, поэтому адреса `/html/mod.html` нет.
- Настройки, которые лежат в файлах пакета (например, `pkg/ИМЯ/conf`), установка новой версии
  заменяет файлом из пакета. Настройки пользователя нужно держать вне файлов пакета.
- Ответ `100003` на `/api/mod/ИМЯ` без входа веб-сервер дает и для несуществующего обработчика.
  Есть ли обработчики на роутере, `install.sh` проверяет сверкой md5 по SSH.
