# Свои вызовы

Справочник для разработчиков панели и моков (`src/frontend/dev/mock/mod/`). Исходники обработчиков — `src/backend/api/mod/`,
единая точка входа — `src/backend/api/vsim/`, помощник — `src/backend/helper/`,
проверки с входом — `src/backend/TESTS.md`.

## Общие правила

Веб-сервер роутера выполняет только пути из подписанного списка
`/app/webroot/WebApp/common/webauth/restfulconfig_common.xml`. Путей `/api/mod/*` в нем нет: после входа они
отвечают `100003`. Поэтому все свои вызовы идут через один путь из списка — `api/vsim/config-vsim`
(виртуальной SIM на 23c нет). Модуль выбирает поле `module`.

| что | как |
|---|---|
| вход | только после входа, без входа — `100003` |
| чтение | `POST /api/vsim/config-vsim`, тело `<request><module>ИМЯ</module><action>show</action></request>`, ответ `<response>…</response>`. Ниже такие разделы помечены «show» |
| действие | `POST /api/vsim/config-vsim`, тело `<request><module>ИМЯ</module><action>ДЕЙСТВИЕ</action>…поля…</request>` |
| состояние помощника | `GET /api/vsim/config-vsim` — то же, что `module=helper`, `action=show` |
| токен | заголовок `__RequestVerificationToken`, как у стоковых POST; без верного токена — `125003` |
| шифрование | можно слать тело зашифрованным, как стоковые пароли (`Content-Type: …;enc`, RSA): веб расшифровывает тело до Lua для любого пути (см. ниже) |
| ответ на действие | `<response>…поля…</response>` |
| ошибка | `<error><code>N</code><message>текст</message></error>`, текст по-русски; у `9004` еще `<output>` |
| многострочный текст в запросе | поле с окончанием `_b64`: UTF-8 в base64 (содержимое скрипта, конфиг VPN) |
| многострочный текст в ответе | обычный текст в элементе (`<output>`, `<content>`), экранированы только `&`, `<`, `>`; переводы строк настоящие |
| простые поля запроса | текст до 512 байт; спецсимволы XML экранировать как обычно (`&amp;`, `&lt;`, `&gt;`, `&quot;`) |
| списки | повторяющиеся элементы внутри элемента-обертки: `<scripts><script>…</script><script>…</script></scripts>` |
| числа | целые, без единиц; единица в имени поля (`_kb`, `_mhz`, `_c`, `_s`, `_pct`) |
| флаги | `0` или `1` |

Неизвестный `module` — `9009` «Неизвестный модуль». Новый модуль добавляется в `NAMES` файла
`src/backend/api/vsim/config-vsim.lua` и в этот справочник.

Веб-сервер роутера однопоточный: пока обработчик ждет помощника, весь веб (и стоковый тоже) не отвечает.
Поэтому долгое (замер скорости, долгий скрипт) идет в фоне, а SPA опрашивает состояние.
Время ответа: обычно 0,1–0,3 с, `signal` — около 4 с, `scripts run` без фона — до `timeout_s`.

### Шифрование тела

Как устроено (по коду `/app/bin/web`, на роутере еще не проверено):

1. Общий обработчик запроса смотрит `Content-Type`: `enc`, `enc;…` или `…;enc` — тело зашифровано. Путь не важен.
2. Одна функция для всех путей принимает тело, расшифровывает RSA (`ATP_SEC_DecryptData`) и раскодирует base64.
3. `do_post.lua` получает уже расшифрованный XML.

Значит, `setconf` с приватным ключом можно слать с `{encrypt: true}`. Проверка — в `TESTS.md`.

## helper

show (или `GET /api/vsim/config-vsim`)

| поле | значение |
|---|---|
| `running` | `1` — помощник отвечает |
| `version` | версия помощника |
| `uptime_s` | сколько секунд работает помощник |
| `modem_write` | `1` — разрешены команды, меняющие модем: `radio set`, AT без `?` |
| `nv_write` | `1` — разрешена запись NV: `cell set`, `cell clear`, `battery set` |

```xml
<response><running>1</running><version>1</version><uptime_s>9</uptime_s><modem_write>0</modem_write><nv_write>0</nv_write></response>
```

Если помощник не отвечает — ошибка `9001` «Помощник не запущен или не отвечает» (во всех модулях, кроме `lanname`).
Сторож помощника проверяет очередь раз в 30 с и после двух неудач подряд перезапускает ее,
так что `9001` держится не дольше минуты.

`set`, поля `modem_write` и/или `nv_write` = `0` или `1`: включить или выключить флаг. Флаг — файл
`/online/mod/helper/modem_write` или `nv_write` (root, 0644); в журнал помощника пишется «флаг X включен» или
«выключен». Ответ — как show. Без полей — `9003`.

| флаг | что открывает |
|---|---|
| `modem_write` | `radio set` (режим сети, диапазоны), AT без `?` в консоли (`at` переходит в `mode=full`) |
| `nv_write` | `cell set`, `cell clear`, `battery set` (пишут NV, нужна перезагрузка) |

Черный список консоли AT (`^PHYNUM`, `^NVWR*`, `+EGMR` и др.) действует при любом флаге.

## sysinfo

show — быстрый (0,1–0,3 с): занятость ЦП считается по разнице с прошлым вызовом. Если прошлого вызова не было
больше 120 с, помощник делает короткий замер 0,4 с.

| поле | значение |
|---|---|
| `cpu_pct` | занятость процессора, % (по `/proc/stat` с прошлого вызова) |
| `cpu_mhz`, `cpu_min_mhz`, `cpu_max_mhz` | частота сейчас, наименьшая и наибольшая, МГц (у роутера 100–666) |
| `mem_total_kb` | ОЗУ всего, КБ |
| `mem_avail_kb` | доступно, КБ. В ядре 3.10 нет `MemAvailable`, поэтому это оценка: свободно + буферы + кэш |
| `mem_avail_est` | `1` — `mem_avail_kb` оценка (на этом роутере всегда `1`) |
| `mem_used_kb`, `mem_used_pct` | занято = всего − доступно, КБ и % |
| `mem_free_kb`, `mem_cached_kb` | свободно и кэш с буферами, КБ |
| `load1`, `load5`, `load15` | средняя загрузка, строкой вида `20.14`. На этом роутере около 20 и без нагрузки (ждущие потоки модема): занятость ЦП по ней не судить |
| `uptime_s` | время работы, с |
| `bat_percent`, `bat_temp_c`, `bat_status`, `bat_present`, `bat_voltage_mv` | батарея; `bat_temp_c` — градусы; `bat_status` как в ядре: `Charging`, `Discharging`, `Full`, `Not charging` |
| `sensors` | `<sensor><name>battery</name><c>37.0</c></sensor>` — температуры, °C с одной десятой, только 4 датчика: `battery` (батарея), `sim_card1` (SIM), `pa0` (усилитель), `xo0` (кварц). Других каналов помощник не читает: чтение неотображенных каналов раньше выключало роутер. Датчика без значения в списке нет |
| `disks` | список `<disk><mount>/online</mount><total_kb>62976</total_kb><used_kb>17412</used_kb><free_kb>45564</free_kb></disk>` |
| `kernel` | версия ядра |
| `fw_version` | версия прошивки (`21.191.63.02.00`) |
| `mod_version` | `bay3255`, если на роутере мод; иначе пусто |
| `helper_version` | версия помощника |

## lanname

Имя роутера в сети (`homeurl` стока) = `DeviceName.DomainName` из настроек LAN
(`InternetGatewayDevice.LANDevice.1.LANHostConfigManagement.`). Модуль работает в самом веб-сервере (через `dm`),
без помощника; помощник нужен только для полей проверки.

show:

| поле | значение |
|---|---|
| `device_name`, `domain_name` | части имени (`www`, `huaweimobilewifi.com`) |
| `homeurl` | имя целиком |
| `lan_ip` | адрес роутера в LAN |
| `dns_ip`, `dns_ok` | что отвечает DNS роутера (127.0.0.1) на `homeurl`; `dns_ok`=`1`, если адрес роутера |
| `web_status`, `web_ok` | код ответа веба на `GET /` с `Host: homeurl`: `200` — пускает, `307` — уводит на 192.168.1.1 |
| `check_error` | вместо полей проверки, если помощник не ответил |

`set`, поля `device_name`, `domain_name` (`domain_name` может быть пустым). Буквы приводятся к строчным.

| проверка | ошибка `9003` |
|---|---|
| `device_name` — одна метка | буквы a-z, цифры, дефис не в начале и не в конце, 1–63 символа |
| `domain_name` — метки через точку | то же для каждой метки |
| окончание `.local` | отказ: `.local` занят mDNS (Bonjour, Avahi), такие имена устройства ищут без DNS роутера |
| длина `homeurl` | не больше 253 символов |

Ответ — как у show, плюс `reboot_needed` (`1`, если настройки просят перезагрузку). Если роутер не принял
имя — `9004` с кодом `dm` в тексте.

Веб пускает страницы, только если `Host` — адрес роутера или текущий `homeurl` (без учета регистра).
Остальное он уводит `307` на `http://192.168.1.1/html/index.html?origin=…`.
Имя для этой проверки веб читает из настроек на каждый запрос (по коду `/app/bin/web`), поэтому новое имя
должно заработать сразу. Ответит ли DNS роутера новым именем без перезапуска `dns`, покажет `dns_ok` после смены.

## msisdn

SIM этого роутера номер не хранит (`AT+CNUM` — ошибка 22, `Msisdn` в `device/information` пуст).
Номер берется из кэша, вводится вручную или узнается запросом USSD у оператора.

show:

| поле | значение |
|---|---|
| `number` | номер вида `+7XXXXXXXXXX` или пусто |
| `source` | откуда номер: `sim` (из SIM), `manual` (введен), `ussd` (от оператора), `cache` (кэш без отметки источника), `none` (номера нет) |
| `iccid` | ICCID текущей SIM |
| `plmn` | оператор SIM (MCC+MNC из IMSI, `25020`) |
| `ussd_code` | код USSD «мой номер» для этого оператора или пусто |
| `ussd_verified` | `1` — код подтвержден на сайте оператора (только такой помощник шлет сам) |
| `ussd_senders` | отправители SMS оператора через запятую (из `ussd-msisdn.txt`), пусто — SMS не разбирать |
| `ussd_sent_at`, `ussd_sent_local` | когда помощник последний раз слал USSD для этой SIM: unix-время и время роутера `2026-10-29 16:58:51` (как `Date` в `sms-list`); пусто, если не слал. Хранится в `msisdn.state`, переживает перезагрузку |
| `last_result` | итог последнего запроса для этой SIM: `none`, `sent` (идет), `ok`, `sms` (ответ без номера), `error` |
| `sms_reader` | `1` — помощник сам читает SMS (поставлен `sms_webhook`); `0` — номер из SMS берет страница |
| `cache_iccid_match` | `1` — кэш записан для этой SIM |
| `roaming` | `1` — роуминг (USSD не шлется) |
| `auto_state` | автозапрос после загрузки: `idle`, `waiting_net`, `pending`, `done`, `sms` (оператор ответил без номера — номер придет в SMS), `failed`, `roaming`, `no_code`, `unverified`, `no_network`, `busy` |
| `attempts` | сколько автозапросов было для этой SIM (не больше 3) |
| `next_try_s` | через сколько секунд следующая попытка (при `pending`) |
| `query_state` | ручной запрос: `idle`, `pending`, `done`, `sms`, `failed` |
| `last_reply` | текст последнего ответа оператора (только цифры и знаки номера, остальное — пробелы); в журнал не пишется |

Порядок: `Msisdn` из `device/information`, если не пуст; иначе кэш, если в нем ICCID текущей SIM; иначе `none`.
ICCID и оператора помощник берет сам (стоковый `device/information` через `web_hook`), от страницы не принимает.

| действие | поля | что делает |
|---|---|---|
| `set` | `number`, `source` = `manual` (по умолчанию) или `ussd` | записать номер для текущей SIM; ответ — как show. Номер приводится к виду `+7…`: `8XXXXXXXXXX` и `7XXXXXXXXXX` → `+7XXXXXXXXXX`, 10 цифр → `+7…`, с `+` — 10–15 цифр; иначе `9003` |
| `parse` | `text_b64` — текст ответа оператора | достать номер: `number`, `found` (`1`/`0`). Понимает `+7…`, `8…`, `7…` с пробелами, дефисами и скобками |
| `query` | — | кнопка «Узнать у оператора»: запрос USSD в фоне, ответ `query_state=pending`; опрашивать show. Номер найден — пишется в кэш (`source=ussd`) |
| `sms` | — | найти номер в SMS оператора, пришедшем после последней отправки USSD для этой SIM, без нового USSD; ответ `found` (`1`/`0`) и поля show. Только при `sms_reader=1`, иначе `9006` |

Ошибки `query`: нет сети или роуминг — `9002`; нет кода для оператора — `9006`; запрос уже идет — `9002`.

**Номер в SMS.** Некоторые операторы отвечают на USSD без номера, а номер присылают отдельным SMS от своего отправителя
(пятое поле `ussd-msisdn.txt`). Стоковый `sms` хранит тексты SMS зашифрованными, поэтому
помощник читает SMS только через `sms_webhook` (библиотека меню экрана, по умолчанию не ставится).

| `sms_reader` | кто берет номер из SMS |
|---|---|
| `1` | помощник: после ответа без номера ждет SMS до 120 с; при загрузке и по действию `sms` ищет SMS, пришедшее после прошлой отправки (без нового USSD) |
| `0` | страница, при `auto_state` или `query_state` = `sms`: шаги ниже |

Шаги страницы (и правила для помощника):

1. Стоковый `api/sms/sms-list`: входящие, новые первыми, не больше 5.
2. Взять только SMS, у которых `Phone` есть в `ussd_senders` (без учета регистра), а `Date` не раньше `ussd_sent_local`.
   Остальные SMS не открывать и не помечать прочитанными (`sms-list` пометку не ставит).
3. Текст подходящего SMS — в `parse` (`text_b64`), найденный номер — в `set` с `source=ussd`.

После ответа без номера новый USSD для этой SIM сам не уходит (только кнопкой `query`).

В журнал помощника идет только «+CUSD: статус, DCS, длина», без текста ответа.
`query` шлет код и со статусом «сторонние» (пользователь нажал кнопку сам).

Автозапрос после загрузки: через 60 с после загрузки помощник ждет домашнюю сеть (до 10 мин),
один раз сверяет ICCID. Если номера нет ни в SIM, ни в кэше для этой SIM, а код подтвержден на сайте
оператора, шлет USSD. Неудача — повторы через 1, 10 и 60 мин, всего не больше 3 на SIM (счетчик переживает
перезагрузку), потом до смены SIM или до кнопки. В роуминге не шлет. Сеанс USSD из стокового веба
помощник не видит: если пользователь в эту минуту сам шлет USSD, запросы могут пересечься.

Файлы:

| файл | что | формат |
|---|---|---|
| `/online/mod/conf/msisdn` | кэш номера (его читает и меню экрана) | одна строка `<ICCID> <номер>\n`, номер вида `+7XXXXXXXXXX`, root:1000 0644, запись через tmp + mv |
| `/online/mod/conf/msisdn.src` | источник номера в кэше | `<ICCID> manual` или `<ICCID> ussd` |
| `/online/mod/conf/msisdn.state` | запросы номера для SIM | `<ICCID> <попыток> <итог> <unix отправки> <дата> <время>`; итог `none`, `sent`, `ok`, `sms`, `error`; при `3` попытках или итоге `sms` автозапрос новый USSD не шлет |
| `/online/mod/helper/ussd-msisdn.txt` | коды USSD по оператору | `MCCMNC\|код\|источник\|дата проверки\|отправители SMS`, `#` — комментарий; источник `официально: …` или `сторонние: …`; отправители через запятую |

Коды на момент проверки:

| MCC+MNC | оператор | код | проверка |
|---|---|---|---|
| 25001 | МТС | `*111*0887#` | официально: media.mts.ru |
| 25099 | Билайн | `*110*10#` | официально: moskva.beeline.ru |
| 25020 | Tele2 (T2) | `*201#` | официально по поисковому индексу msk.t2.ru/help/article/check-your-number (сам сайт отвечает 503); номер приходит SMS от `t2.ru` |
| 25002 | МегаФон | `*205#` | только сторонние сайты: на moscow.megafon.ru/help кода нет |
| 25011 | Yota | `*103#` | только сторонние сайты: на yota.ru/support кода нет |

Чтобы помощник сам слал код со статусом «сторонние», поменяйте в файле источник на `официально: <ссылка>`
после проверки на сайте оператора.

## signal

show:

| поле | значение |
|---|---|
| `stock` | поля стокового `api/device/signal` как есть: `pci`, `cell_id`, `rsrp` (`-88dBm`), `rsrq`, `rssi`, `sinr`, `band`, `earfcn` (`DL:3400 UL:21400`), `dlbandwidth`, `ulbandwidth`, `tac`, `plmn`, `nei_cellid`, `mode`, … |

## speedtest

Замер идет в фоне: `run` сразу отвечает `status=running`, SPA опрашивает show раз в секунду. Каждый запрос занимает процессор, и замер получает меньше, поэтому чаще не опрашивать и другие запросы на время замера не слать.
Во время замера помощник каждые 250 мс пишет занятость ЦП и скорость приема — для живого графика, без `sysinfo`.

Порядок при `streams` больше 1: прием, прием в несколько потоков, отдача, отдача в несколько потоков. Каждая фаза идет до `timeout_s` или до предела объема. Длительность — до четырех `timeout_s`.

Скорость считается по счетчику байт интерфейса (через туннель `awg0`, напрямую внешний интерфейс) после разгона: от первой точки не раньше 2 с до конца передачи. Счетчик включает заголовки и чужой трафик на этом интерфейсе. В фазах потоков конец отрезка — последняя точка до завершения первого потока, если отрезок не короче 0,5 с. Фаза короче 2 с считается целиком. Длина отрезка — в `window_s`, `mt_window_s`, `up_window_s`, `up_mt_window_s`.

Предел объема на фазу:

| `streams` | прием | потоки приема | отдача | потоки отдачи | всего, не больше |
|---|---|---|---|---|---|
| `1` | 30 МиБ | — | 12 МиБ | — | 42 МиБ |
| `2`–`4` | 16 МиБ | 30 МиБ | 6 МиБ | 12 МиБ | 64 МиБ |
| `2`–`4`, `via=awg` | 16 МиБ | 30 МиБ | 6 МиБ | 12 МиБ | 58 МиБ |

Предел фазы потоков уменьшается, если прошлые фазы уже заняли много. На поток приходится предел фазы, деленный на `streams`. Если предел срабатывает раньше времени, отрезок после разгона короче, а скорость на быстрой связи занижена. По счетчику внешнего интерфейса 64 МиБ — около 72 МБ, 58 МиБ через туннель — около 71 МБ. Сколько ушло на самом деле — в `traffic_mb`.

Сколько качать (прием): не дольше `timeout_s` (по умолчанию 8 с) и не больше предела фазы одним запросом; файл кончился раньше — запрос повторяется.
Отдача: нули (`/dev/urandom` на этом ЦП дает 8 МиБ за 4,9 с и сам ограничивал бы скорость), не больше объема из таблицы и не дольше
`timeout_s`, одним соединением, чтобы на графике не было пауз на рукопожатие:

| `up_mode` | как шлет | когда |
|---|---|---|
| `single` | один `POST` на весь объем | обычно |
| `chunks` | `POST` по 1 МиБ подряд по одному соединению (`curl --next`) | HostKey (413 от 2 МиБ) и сервер, не принявший большой `POST` |
| `chunks_est` | то же, но за время замера не закончился ни один кусок: байты по счетчику отдачи интерфейса, время по часам | медленная связь |

Обрыв по общему времени ошибкой не считается: отданное до него идет в расчет.
Если большой `POST` получил отказ или не прошло рукопожатие (на соединение 3 с), помощник в пределах времени переходит на куски.

Список серверов — `/online/mod/helper/speedtest-servers.txt`, строки
`id|название|страна|url|размер_байт|range|https|медиана_Мбит/с|upload_url` (`#` — комментарий; 9-е поле
`upload_url` — адрес для замера отдачи, пусто или нет поля — отдачи у сервера нет).
С `range=1` объем задает запрос `Range`, без него запрос обрывается по достижении объема.
Если файла нет — один сервер
`selectel` (`http://speedtest.selectel.ru/10MB`). Качает `curl` из пакета `dns`
(`/online/mod/pkg/dns/bin/curl`, HTTP и HTTPS); без него — только `http://` через `nc`.

`servers`:

| поле | значение |
|---|---|
| `curl` | `1` — есть `curl` (HTTPS, отдача и автовыбор работают) |
| `servers` | `<server><id>…</id><name>…</name><country>RU</country><url>…</url><size_bytes>…</size_bytes><range>1</range><https>0</https><median_mbps>…</median_mbps><upload_url>…</upload_url></server>` |

`run`, поля:

| поле | значение |
|---|---|
| `server` | `id` из списка или `auto` (по умолчанию): из 3 серверов с лучшей медианой берется тот, к которому быстрее соединение (`curl -w time_connect`); при `direction=up` — только среди серверов с `upload_url`. Выбранный `id` — в поле `server` результата: для «Сравнить» повторите `run` с этим `server` и другим `via` |
| `direction` | `down` — прием, `up` — отдача, `both` — сначала прием, потом отдача (по умолчанию). При `both` у сервера без `upload_url` отдача идет на другой сервер: с самым быстрым соединением среди имеющих `upload_url`, по тому же пути (`up_server`). `up` у сервера без `upload_url` — `9006` |
| `url` | вместо `server`: свой адрес `http://` или `https://` |
| `timeout_s` | сколько качать не дольше, с: по умолчанию 8, от 3 до 60 |
| `via` | пусто — напрямую; `awg` — через туннель AmneziaWG (`curl --interface awg0`, точки скорости — по `awg0`), и прием, и отдача. Туннель не поднят или нет `curl` — `9006` |
| `streams` | сколько одновременных `curl` в фазах потоков: от 1 до 4, по умолчанию 4. `1` — без фаз потоков. Другое значение — `9003`. Значение больше 1 без `curl` — `9006`; без поля и без `curl` замер идет в один поток |

Ответ `run`: `status=running`, `server`, `url`, `direction`, `streams`, `via`. Если замер уже идет — `9002`.

| `split_hint` | только `awg`: совет про DNS, если режим включен, а DNS клиентов идет к оператору; иначе пусто |
| `split_direct`, `split_vpn` | только `awg`: свои адреса «всегда напрямую» и «всегда через VPN»: `<split_direct><addr>203.0.113.0/24</addr>…</split_direct>` |
| `failover`, `primary` | только `awg`: `1` — переключение профиля при обрыве включено; основной профиль |
| `failover_reason` | только `awg`: последнее решение цикла: `ok`, `on_backup`, `switched`, `returned_primary`, `primary_still_down`, `operator_down`, `pause`, `no_other_profile` (профиль один, цикла нет), `no_full_tunnel` (в туннель идет не весь трафик, цикл ничего не переключает), `tunnel_down`. Смысл каждого — в `src/pkg/awg/README.md`, раздел «Переключение при обрыве» |
| `dns_mode`, `dns_server` | только `awg`, из `svc.sh status` (строки `dns=`, `dns_server=`): куда идут DNS-запросы клиентов LAN — `tunnel` (через туннель на `dns_server`), `operator` (DNS оператора), `dnspkg` (пакет `dns`); пусто, пока пакет этих строк не печатает |

Действия, поле `type` = `wg`, `ovpn` или `awg`:

| action | поля | ответ |
|---|---|---|
| `start` | — | элемент `<wg>`, `<ovpn>` или `<awg>` с состоянием, `output` |
| `stop` | — | состояние |
| `autostart` | `enable` = `0` или `1` | состояние; `wg` и `ovpn` стартуют через 60 с после загрузки, `awg` — как пакет (`svc.sh enable`) |
| `config` | `name` (только `awg`, необязательно: иначе активный профиль) | `content` — конфиг; у `awg` строки `PrivateKey` и `PresharedKey` заменены на `(скрыт)`, плюс `name` |
| `save` | `content_b64` (не больше 64 КБ) | состояние |
| `setconf` | `conf_b64` (не больше 64 КБ); для `awg` еще `name` — обязательно, `label` — необязательно | то же, что `save`; для `awg` конфиг уходит в `svc.sh setconf <name> [label]` через стандартный ввод (пакет без профилей — `svc.sh setconf` без имени) |
| `profile_use` | только `type=awg`, `name` | сделать профиль активным: `svc.sh use <name>`; ответ — `<awg>` с состоянием |
| `profile_delete` | только `type=awg`, `name` | удалить профиль: `svc.sh delete <name>`; ответ — `<awg>` |
| `profile_label` | только `type=awg`, `name`, `label` | сменить подпись: `svc.sh label <name> <label>`; ответ — `<awg>` |
| `dns` | только `type=awg`; `on` = `1` или `0` | DNS клиентов LAN через туннель — `svc.sh dns on` или `off`, туннель не останавливается; ответ — `<awg>` с состоянием. Пакет без команды `dns` — `9004` «Пакет AmneziaWG не умеет переключать DNS» |

Раздельный VPN и переключение профиля, только AmneziaWG, поле `type` не нужно. Ответ — `<awg>` с состоянием и `output`:

| action | поля | что делает |
|---|---|---|
| `split` | `on` = `1` или `0` | включает или выключает раздельный VPN без перезапуска туннеля: `svc.sh split on` или `off` |
| `split_update` | `list_b64` — файл списка в base64 | проверяет и заменяет список российских адресов: `svc.sh split-update`. Размер файла — не больше 270 КБ: поле `list_b64` ограничено 360000 символами |
| `split_direct` | `op` = `add` или `del`, `addr` | свой адрес или подсеть «всегда напрямую»: `svc.sh split-direct` |
| `split_vpn` | `op` = `add` или `del`, `addr` | свой адрес или подсеть «всегда через VPN»: `svc.sh split-vpn` |
| `failover` | `on` = `1` или `0`, `primary` — необязательно | включает или выключает переключение при обрыве: `svc.sh failover`. `primary` — основной профиль, по умолчанию активный |

`addr` — IPv4 или подсеть, например `203.0.113.0/24`; другая запись и неверное значение `on`, `op`, `primary` — `9003`.
Отказ пакета — `9004`, в `message` его текст как есть: «нет списка российских адресов: загрузите файл», «нужно хотя бы два профиля».
Нет пакета — `9006`.

Имя профиля AmneziaWG: `a-z`, `0-9`, `_`, `-`, от 1 до 32 символов (`AWG3.1` — нельзя, `awg3_1` — можно); иначе `9003`.
Подпись (`label`): UTF-8, от 1 до 64 символов, без перевода строк и управляющих символов; иначе `9003`.
В ответе подпись экранирована для XML (`&amp;`, `&lt;`, `&gt;`).
Пакет без команд профилей: `profile_use`, `profile_delete` — `9004` «Пакет AmneziaWG не умеет работать с профилями».

Файлы: WireGuard — `/online/vpn.conf` (тот же, что у меню экрана, формат `wg setconf`),
OpenVPN — `/online/mod/vpn/openvpn.conf`, AmneziaWG — профили `/online/mod/conf/awg/profiles/<имя>.conf`,
активный — `/online/mod/conf/awg/active`, без профилей — `/online/mod/conf/awg/awg0.conf` (пишет пакет).
Приватный ключ AmneziaWG не попадает в ответы и журналы: из вывода пакета убираются строки с `PrivateKey`
и `PresharedKey`, из `status` берутся только поля, перечисленные в таблице `show`.
`setconf` лучше слать зашифрованным (см. «Шифрование тела»).
Пакета нет — `start`, `stop`, `autostart`, `setconf` отвечают `9006`.

## svc

Пакеты (обход блокировок, DNS): `/online/mod/pkg/<имя>/svc.sh` (команды `start`, `stop`, `status`, `enable`, `disable`),
описание — первая строка `/online/mod/pkg/<имя>/desc`.
`svc.sh status` печатает строки `running=0|1`, `enabled=0|1`, `info=<текст>`; без строки `running=` берется код выхода (0 — работает).

show:

```xml
<response><services>
  <service><name>zapret2</name><desc></desc><running>1</running><enabled>0</enabled><info>очередь 200, правила: есть, память 1396 КиБ</info></service>
</services></response>
```

Поле `name`, действия `start`, `stop`, `enable`, `disable`, `status`.
Ответ: `name`, `rc`, `running`, `enabled`, `info`, `output`.

Пакет `dns` в show и в ответах своих действий добавляет поля:

| поле | значение |
|---|---|
| `preset`, `preset_label` | выбранный сервер DNS и его подпись (`auto`, «Авто: Cloudflare (DoT)») |
| `custom_addr` | адрес своего сервера для пресета `custom`, пусто — не задан. У `https://` путь перед `dns-query` заменен на `…`: в нем может быть личный ключ. Для `dns_custom` адрес вводится заново |
| `adblock` | `1` — блокировка рекламы включена |
| `dns_upstream` | куда сейчас идут запросы: `preset` — выбранный сервер, `backup` — запасные серверы, `operator` — DNS оператора (заблокированные сайты не открываются) |
| `dns_fallback` | `1` — выбранный сервер не отвечает, работает запасной вариант из `dns_upstream` |
| `user_off` | `1` — службу выключил пользователь, сама она не поднимется |
| `last_error` | текст последней ошибки пакета из `svc.sh status`; пусто — ошибки нет |
| `recommended` | `id` рекомендуемого сервера, на него указывает `auto` |
| `presets` | список `<dns_preset><id>quad9-dot</id><label>Quad9 (DoT)</label><active>0</active></dns_preset>`, первым идет `auto`; имя `dns_preset`, потому что `<preset>` занято полем выше |

| действие | поля | что делает |
|---|---|---|
| `dns_preset` | `id` | выбрать сервер DNS |
| `dns_custom` | `addr` — `https://сервер/dns-query`, `tls://имя` или IPv4 | задать адрес для `id=custom`; после него нужен `dns_preset` с `id=custom` |
| `dns_adblock` | `on` = `0` или `1` | выключить или включить блокировку рекламы |
| `dns_enable` | — | включить службу: автозапуск и запуск (`svc.sh enable`, затем `start`) |
| `dns_disable` | — | выключить службу: остановка и снятие автозапуска (`svc.sh stop`, затем `disable`). Одной остановки мало: пока включен автозапуск, служба поднимется снова |

Ответ действий — как у `status` для `dns`: `name`, `running`, `enabled`, `info`, поля выше, `output`. Служба от этих действий
не запускается: остановленная только запоминает выбор, запущенная применяет его сразу (DNS клиентов молчит 1–2 с).
Отказ пакета — `9004`, в `message` его текст как есть («нет пресета: nosuch»). Недопустимые символы в `id` и `addr` — `9003`.

## logs

show — список: `<logs><log><id>dmesg</id><title>Ядро</title></log>…</logs>`;
`id`: `dmesg`, `helper` (журнал помощника), `scripts` (запуски скриптов), `ovpn`, `logcat`.

`get`, поля `id`, `lines` (по умолчанию 200, от 1 до 2000). Ответ: `id`, `output`.

## radio

show:

| поле | значение |
|---|---|
| `mode` | `00` авто, `03` только 4G, `02` только 3G, `01` только 2G, `0302` 4G и 3G, `0301` 4G и 2G, `0201` 3G и 2G |
| `lte_mask` | маска диапазонов LTE из `^SYSCFGEX?` (`2000000045` = B1, B3, B7, B38) |
| `lte_bands` | `<band><num>7</num><on>1</on></band>` для B1, B3, B7, B8, B20, B28, B32, B38 |
| `output` | сырой ответ `AT^SYSCFGEX?` |

`set`, поля `mode` и/или `bands` (номера через запятую: `1,3,7`). Остальные поля `^SYSCFGEX`
не меняются. Ответ — как у GET. Пока `modem_write`=`0` — ошибка `9008`.

## battery

show отвечает полем `nobattery`: `1` — включен режим работы без батареи (ячейка NV 50364).

`set`, поле `nobattery` = `0` или `1`. Ответ: `nobattery`, `reboot_needed`=`1`.
Пока `nv_write`=`0` — ошибка `9008`.
